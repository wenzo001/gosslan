# v2.2 说明 — 紧凑、圆润、苹果式的清晰

日期：2026-11-06。v2.2 不推翻 v2.1 的方向，而是在“微信 / QQ / 飞书的熟悉感”上再加三条约束：

1. **更紧凑**：减少行高和空白，让 1000×680 的主窗口和 780×600 的设置窗口能放下更多信息。
2. **更圆润**：统一同心圆角，控件 10px、卡片 16px、气泡 20px、抽屉/输入外壳 22px。
3. **复杂页面更清楚**：参考 Apple 设置 / 文件 App 的分组方式，用分组卡片、固定槽位和最多两行摘要，而不是把字缩小。

## 1. 为什么是苹果式，而不是苹果外观

将来要上架 Mac App Store，苹果用户对下面这些已经很熟悉：

- 系统字体、明确的字号层级、数字对齐；
- 连续圆角、同心嵌套、克制的阴影；
- 设置页按“分组卡片 + 一行一个决定”组织；
- 信息密度可以高，但每一行只有一个视觉重点。

不照搬的地方：

- **不做玻璃材质**：Tauri 跨平台窗口、私网团队工具，实色表面更稳定，也不会在不同系统上失真。
- **不做超大标题**：主窗口只有 1000×680，营销式大标题会挤压会话。
- **不引入 iOS 独占控件**：开关、分段控件、底部抽屉用跨平台等价物，尺寸按 44px 触控目标。
- **保留微信/飞书的 IA**：左 rail、会话列表、聊天、4 tab、顶栏「+」都不变。

## 2. 具体数字

| 项 | v2.1 | v2.2 |
| --- | --- | --- |
| 桌面会话行 | 68px | **62px** |
| 移动会话行 | 68px | **64px** |
| 行内头像 | 46px | **42px** |
| 设置行 | 约 56px | **48px** |
| 聊天 / 页面头 | 54–56px | **52px** |
| 移动底部 tab | 60px | **56px** |
| 控件圆角 | 8–10px | **10px** |
| 卡片圆角 | 12–14px | **16px** |
| 气泡圆角 | 18–20px | **20px**（连接角 6px） |
| 抽屉 / 输入外壳 | 18–22px | **22px** |
| 辅助字号 | 8.5–12px | **≥10.5px，常规 ≥11px** |

同心圆角规则：**内层圆角 = 外层圆角 − 间距，最小 8px**。例如 16px 卡片 + 8px 内边距 → 内层 8px；22px 抽屉 + 8px 内边距 → 内层 14px。

## 3. 复杂页面怎么变清楚

以设置、任务中心、搜索、群资料为例：

- **分组卡片**：16px 圆角，组内用发丝线，组间 12–16px；不再用一整张大表。
- **固定槽位**：右侧值、开关、时间、未读固定；中间文本 `min-width:0` + 单行省略。
- **最多两行**：搜索摘要、任务路径、错误原因最多两行；完整内容去详情看。
- **技术串等宽断行**：IPv6、安全码、文件路径允许任意断行，绝不横向溢出。
- **字号下限**：正文 13–14px，辅助 11px；密集卡片最低 10.5px，不再出现 8.5px。

## 4. 边界情况

长文本、URL、文件名、99+、Toast、输入草稿等完整规则见 [edge-cases.md](edge-cases.md)；可视化在画布 `05 Edge cases`：

- `DesktopEdgeCases.dc.html`：会话列表、聊天、文件任务、好友资料、搜索设置、浮层六类。
- `MobileEdgeCases.dc.html`：列表与聊天两台 390×844，加移动端收束规则。

## 5. 品牌：小院与 Rounded 2.0

- **小院**：蓝色院墙（squircle）+ 奶油拱门 + 绿苗。无表情版本用于导航/角标/App 图标；有表情版本用于空态、欢迎页和状态页。
- **应用图标**：1024 满版蓝底 + 奶油拱门 + 绿苗；macOS 22.37% 圆角，iOS/Windows 满版，Android 66% 安全区，Tinted 单色；16px 小苗收成绿点。
- **图标**：24 网格、2px 圆头描边；收藏改为书签，设置改为两条滑杆；导航、发送、附件、返回、更多等高频图标已替换。
- **落地**：空态已经使用小院标记；源文件在 `brand/`，画布在 `06 Brand`。

## 6. 需要你确认

1. 62px / 64px 行高是否够紧凑？还能再压到 58px，但触控和呼吸感会变差。
2. 气泡 20px、卡片 16px、抽屉 22px 的圆润度是否合适？要不要更圆（气泡 22px）？
3. 辅助字号抬到 11px 后，密集页面是否能接受略少的信息量？
4. 设置/任务/搜索继续用“分组卡片”，还是更接近 macOS 的整列列表？
