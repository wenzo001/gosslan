# 功能闭环与缺口审计

这份审计回答三件事：

1. 现有每个路由、窗口、浮层、状态，在 v1 设计里有没有落点？
2. 哪些流程「开始有、结束没有」或「失败后没有下一步」？
3. 哪些交互不符合直觉，建议怎么改？

标记说明：**已覆盖** = v1 有画板；**部分** = 有关键画面但缺状态；**缺口** = 没有专门设计，需要补；**不设计** = 内部工具或刻意无 chrome。

## 六、明显不直观的地方（建议改）

1. **添加好友用半透明遮罩弹窗**：在桌面端遮罩只到标题栏，产生「没盖全」的感觉；且发现设备是一件有探索感的事，塞进 440px 弹窗太局促。建议改成**整页发现页**：渐变背景、附近的人卡片、通道状态、邀请码入口，返回即回原页。
2. **搜索是「一次性」的**：关闭搜索就丢结果；从结果跳转后想回搜索只能重来。建议保留搜索覆盖层，跳转后提供「返回搜索」胶囊。
3. **个性化入口太深**：主题色在「外观」、气泡配色在「聊天样式」，用户要改一套「我的风格」要跑两页。建议合并为「个性化」一页，带实时预览。
4. **图片预览与文件传输是两套语言**：图片有灯箱，文件只有卡片。建议统一为「媒体查看器」：图片/文件/合并卡片都能预览、左右切换、另存、定位。
5. **群资料只有成员 tab**：文件、任务 tab 没有对应画面，用户不知道点进去长什么样。建议每个 tab 都有独立状态。
6. **传输完成后没有下一步**：进度到 100% 就消失，用户不知道去哪打开。建议完成后保留 3 秒「打开」入口，并进入任务中心历史。
7. **离线队列不可见**：输入框提示「排队中」，但没有「队列里有什么」。建议点头部状态弹出队列摘要。
8. **多选批量操作没有入口**：长按只能操作单条。建议消息多选模式 + 底部批量条。
9. **强提醒没有回执**：发了强提醒后不知道谁确认了。建议在消息下显示「已确认 2/3」。
10. **群任务窗口在 780px 用看板会挤**：v1 用「列表 + 详情」是合理的；如果坚持看板，建议只显示 3 列并横向滚动。

## 七、需要产品确认的问题

1. **主题色是否同步给聊天对象？** 现有代码里气泡配色会同步，主题色看起来是本地的。设计上需要明确：主题色只影响自己，还是也改变对方看到的气泡？
2. **好友申请被拒绝，发送方要不要收到反馈？** 现在没有明确状态；如果要，给「未通过」还是静默？
3. **消息多选/批量删除是否在现有能力内？** 代码里有批量操作，但设计里还没出图；v2 可以补。
4. **自定义气泡颜色是「双色渐变」还是「单色 + 文字色」？** 现有 6 套预设是双色条；如果允许完全自定义，需要定义可读性边界。
5. **离线队列在应用退出后是否持久化？** 设计里写了「重连后自动发送」，需要确认进程被杀后是否仍保留。
6. **图片/文件「已清理」后能否重新获取？** 群文件可以重新获取，单聊图片/文件不一定；预览器需要区分「本地已清理」与「对端可重取」。
