# 背景动态（Ambient Motion）规格

> v0.5 · 2026-11-05（数值回填，与实现口径对齐）· 目标态规格，不是强制规范
> 上位规范仍是 [docs/design-guidelines.md](../design-guidelines.md)（尤其 §11.3.7 动效五条硬约束）；本文只回答“背景怎么动”，不覆盖内容层动效、消息入场、Toast 动画。
> 分层（L0 ambient / L1 content / L2 chrome / L3 float / L4 modal）沿用 [liquid-glass.md](./liquid-glass.md)。
>
> **v0.2 修订依据**：实测亮色 α 4% / 6% / 8% 三档的**全图平均通道差只有 0.42、多数区域 1–2 色阶**，肉眼几乎不可分。可见性由那层约 28% 的薄纱底色主导，α 只负责“染色”。因此 §3.4 把“存在感”的调法改为**色彩浓度为主、尺寸/薄纱为辅、α 最弱**，并新增可机器判定的档位色差门槛（§7 AM-13）。
>
> **v0.3 修订依据**：AM-13 的采样区原来定在“画面正中 64×64”，实测量到的三档差只有 **0.08–0.10 色阶**。原因是中点被**静态 D 团（约 42% plateau）**覆盖，动的三团按 ≤3vmax 走不到那儿 —— 等于在“调 A 团”的地方测“D 团”。因此 §7 把采样区改为**动团实际走过的覆盖带**，另立中点稳定性判据；并强制**同相位**比较（否则测到的是相位差），判据拆成“档间差”与“动感”两条。
>
> **v0.4 修订依据（用户授权，不是自放宽）**：用户原话“还是太浅，饱和度有点低，希望更明显一些，其实可以到 30% 到 50% 的透明度；要有一点色彩但不要太浓重；不要超过文字”。因此 **v0.3 的“α 固定 6% / 7%、禁止 α 分档”作废**，改为 §3.3 的**带前提 α 区间**：色团 α 允许 **15%–40%**、四档 **15% / 22% / 30% / 38%**，前提是正文承载面一律不透明（alpha ≥0.95）、画布直绘文字 ≥4.5:1、中央 40%×40% 边缘加权留白。性能硬线与同相位采样要求不变。
>
> **v0.5 修订依据（回填实现口径）**：v0.4 的 α 四档 15 / 22 / 30 / 38% 仍低于用户授权区间与下给实现的那组数。v0.5 起文档与实现统一为 **α 亮 20% / 30% / 40% / 48%、暗 16% / 26% / 36% / 44%（-4pp）**，允许区间 **15%–50%**，**默认档 30%（亮）/ 26%（暗）**（用户看过四档图后选定 T2）；S 收敛为**单值 30%**（不再分四档）；B/C 两路副光**常驻且与 A 共用同一个 α**（不再按 T3/T4 启用）。各团合成值已算好写进 §3.3 的表，不需要实现方自己乘倍数。这套数值已经由**用户眼睛确认**定档（2026-11-05 选定 T2）。

> **v0.6 修订依据（AM-13 实测，2026-11-09）**：v0.5 的四档在 T3↔T4 只差 8pp（40%→48%），`--only=ambient` 实测动团带平均 ΔE00 **1.43**（A 1.14 / C 1.82 / B 1.33），低于 §7 AM-13① 的 1.5；T1↔T2（1.64）与 T2↔T3（1.74）都过。按 §3.4「先抬 α、再扩尺寸」的处理顺序，把 T4 抬到**用户授权区间上限 50%**（暗色仍 -4pp ⇒ 46%）：实测 T3↔T4 **1.84**，四档三色相的最坏正文对比度 **5.32:1**（AM-08 仍 ≥4.5），AM-14 中点 0.00。**默认档 T2（30% / 26%）不动**，T1/T3 不动；单点两团合成峰值随之 73%→**75%**（暗 69%→**71%**）。v0.5 修订说明与授权表保留原文，作为历史记录。

## 0. 结论（先看这段）

**推荐组合：3 团极慢漂移的主色雾（72 / 96 / 120s，α 四档亮 20% / 30% / 40% / 50%、暗 16% / 26% / 36% / 46%，默认 30%）+ 1 团静态底洗 + 1 张 α 3% 的静态颗粒 + 只在主按钮按下时的一次局部涟漪。不做全局水波，不用 WebGL，不用 rAF。**

| 项 | 取值 |
| --- | --- |
| 常驻动画元素 | 3 个（3 团漂移色雾）；上限 4 |
| 色团总数 | 4（3 动 + 1 静） |
| 存在感主旋钮 | **色团 α**（亮 20% / 30% / 40% / 50%，暗 16% / 26% / 36% / 46%；允许区间 15%–50%，**默认档 30% / 26%**）；S 固定 30% |
| 单团透明度 | A/B/C 三团共用档位 α；D 固定 4%（静，`--ambient-alpha-d`，不跟档走）。**实际数值与合成值见 §3.3 的表**；前提是正文面不透明 |
| 正文承载面 | 消息气泡 / 卡片 / 输入框 / 列表行背景 **alpha ≥ 0.95**（判据 AM-15） |
| 画布直绘文字 | 空状态 / 时间戳 / 分组标题在最坏合成底上 **≥4.5:1**，不达标降该层 α 或加局部实色底（AM-16） |
| 构图 | 边缘留色、**中央 40%×40% 留白**；主色 + 暖沙（B）+ 冷蓝灰（C），**B/C 与 A 共用同一个 α、四档全开**，不三色齐上 |
| 周期 | 72s / 96s / 120s，`ease-in-out` + `alternate`，负延迟错相 |
| 位移动幅 | 平移 ≤3vmax，缩放 1.00→1.05 |
| 颗粒 | 96×96 平铺 PNG，亮 3% / 暗 4%，**不参与任何动画** |
| 涟漪 | 560ms，同时最多 2 个，只在控件内部裁切，不做全屏层 |
| 档位可辨性 | 动团带内相邻两档 **ΔE00 ≥ 1.5**；同一档 t=0 与 t=+20s **ΔE00 ≥ 1.0**（§7 AM-13） |
| 中点稳定性 | 画面正中 64×64 任意两档 **ΔE00 ≤ 0.5**（中点由静态 D 团覆盖，只用来判“不干扰正文”） |

**三条性能硬线**（写死在 §4，任何实现不得绕过）：

1. 只允许 `transform` / `opacity` 参与动画；禁止动画 `filter` / `blur` / `background-position` / `box-shadow` / 几何属性。
2. 不允许任何逐帧 JS：无 `requestAnimationFrame` 循环、无 `setInterval`、无 canvas / WebGL；所有位移走 CSS keyframes。
3. `document.hidden` 暂停、`prefers-reduced-motion` 冻结在初始帧；空闲 CPU <1%、滚动 p50 不劣于当前 17ms、常驻动画 ≤3 个。

## 1. 候选方案对比

| # | 方案 | 观感 | 成本 | 风险 | 适合谁 |
| --- | --- | --- | --- | --- | --- |
| A | 极慢漂移色雾（mesh gradient drift） | 最接近“高级但不说话”的底色：远看是呼吸的灰，近看才有色相 | 低：3–5 个预栅格化 div，只动 `transform` | 透明度失控会带色偏、出现 banding；色团太多会“花” | **常驻应用背景**（桌面 + 平板） |
| B | 呼吸式光晕 / aurora | 更“有机”、聚焦，暗色下像星空/极光 | 低–中：`opacity` 呼吸 + 少量位移 | 容易变成“呼吸灯”，节律感抢注意力；周期短于 20s 必翻车 | 暗色主题、启动页、空状态页，**不常驻** |
| C1 | 真流体/水波（WebGL / canvas 逐帧） | 最接近苹果演示视频里的“流体壁纸” | 高：GPU 常驻、每帧 fragment 计算、耗电 | 与空闲 CPU 0.09% / 无 rAF 长驻的红线直接冲突；低端机必卡 | 一次性引导页、发布会 demo，**不进入常驻 UI** |
| C2 | 仅交互涟漪（按压/点击） | 有反馈、不占背景，用户主动触发 | 极低：一次 `transform` + `opacity` 短动画 | 全屏铺开会变成“到处都在动”；鼠标端可能显得廉价 | **按钮/发送键的按压反馈** |
| D | 细颗粒 noise | 材质感，压住渐变的色带，让色雾看起来是“实体” | 极低：一张静态贴图，零动画 | α 过高会糊字、显脏；若用 CSS 生成噪点则 CPU 高 | 任何渐变背景的**下层**，3%–4% |
| E | Apple 系统壁纸式“流体壁纸” | 通透、随锁屏/桌面缓慢变化，几乎无循环接缝 | 不可移植：由系统合成器/壁纸进程驱动，WebView 拿不到同层权限 | 在 Tauri WebView 里复制必然降级成“JS 逐帧”，直接撞红线 | 只作**参数参考**：极慢、低对比、无可见接缝 |
| F | Material 3 Expressive 动态色彩 | 主题色驱动的整体色调与形状语言，切换时“有生命” | 低：颜色角色 + 状态转场 | 它是**状态转场**与色彩推导，不是背景常驻动画；当成背景动画会误读 | 跟随用户主题色的**取色规则**（我们的色团就应读 `--gosslan-primary`） |
| G | Windows Mica / Mica Alt 流变 | 安静、几乎察觉不到的壁纸采样，窗口像一块磨砂玻璃 | 低：一次性采样 + noise | 官方 Mica 本身**不平移**；它解决的是“窗口材质”，不是“要有动态” | 桌面窗口框架的**材质**参考；不满足“背景在动”的诉求 |
| H | 滚动视差（parallax，CSS scroll-driven） | 内容滚动时背景轻微跟随，空间感强 | 中：滚动期间持续合成 | 本仓滚动在内层容器，且滚动时再叠一层动画会让帧时间变差；“背景跟着动”也抢注意力 | 营销页、长图页面，**不用于聊天主界面** |

补充说明：

- **E / F / G 不是“第四个候选”，而是“不该抄的部分”**：Apple 的效果由系统合成器承担，M3 Expressive 的动态在色彩角色与状态转场上，Mica 是静态采样。三者共同的可借用结论只有一条：**慢、低对比、没有可见的循环起点**。
- **C1 为什么直接排除**：本仓刚测出空闲 CPU 0.09%、无 rAF 长驻（见 [check-ui-runtime.mjs](../../scripts/check-ui-runtime.mjs) 的 perf 段与长空闲段）。一个常驻 WebGL 背景会把“空闲”从毫秒级变成持续 GPU 占用，这不是调参能救的，是机制冲突。
- **H 为什么排除**：`body` 自身不滚动（滚动都在内层容器），做视差要么监听滚动（JS 逐帧），要么用 `animation-timeline: scroll()`（滚动期间持续合成），两条都会让滚动 p50 变差。

## 2. 推荐组合与理由

**A（漂移色雾，打底）+ D（颗粒，压噪）+ C2（按压涟漪）+ 一团静态底洗。**

1. **和现状同构，只升级“会不会动”。** 当前 `html.ambient` 已经是一层极淡的 `radial-gradient`（[style.css](../../src/style.css#L361-L370)）。新方案把它拆成几个预栅格化的 div，用 `transform` 漂移，机制不变、观感上限提高，不引入第二套背景体系。
2. **全部落在合成层上。** 3 个 div 各自栅格化一次，之后每帧只改 `transform`；GPU 合成，不重绘、不重排，空闲时几乎不产生 JS 任务。
3. **正好满足玻璃的“可采样”前提。** [README](./README.md) 原则 2 说玻璃背后必须有东西可采样；色雾是给 `glass-1/2/3` 提供缓慢变化的底，而不是和内容抢戏。
4. **涟漪只在用户主动按下时出现。** 它是反馈，不是背景；生命周期 560ms，天然不会常驻，也不会破坏“空闲 CPU <1%”。

**明确不做全局水波**：需要逐像素扰动 ⇒ WebGL/canvas 逐帧 ⇒ 撞硬线；而且全屏持续变形会让文字边缘“游动”，直接违反“柔和不喧宾夺主”。

## 3. 可实施规格

### 3.1 层叠顺序与挂载位置

沿用 [liquid-glass.md](./liquid-glass.md) 的 L0–L4：

| 层 | 内容 | z / 说明 |
| --- | --- | --- |
| L0-0 | 薄纱底色（veil，约 28% 基准） | 整屏一层，静态；**可见性主要由它决定**（§3.3 实测） |
| L0-a | 漂移色雾 3 团 | `position: fixed; inset: 0; z-index: 0`，`pointer-events: none`，`aria-hidden="true"` |
| L0-b | 静态底洗 1 团 + 颗粒 1 张 | 与 L0-a 同容器，排在色雾之后（更靠近内容） |
| L1 | 消息列表、气泡、正文 | 内容层，实色，不透明 |
| L2 | chrome 玻璃（标题栏/侧栏/TabBar/输入区外框） | 采样 L0 + L1 |
| L3 / L4 | 浮层 / 模态 | 采样下方所有层 |

**硬约束（会被 `backdrop-filter` 的 backdrop root 规则惩罚）：**

- ambient 容器必须是**玻璃元素的兄弟或更外层**，**绝不能成为任何玻璃元素的祖先**。祖先链上出现 `opacity < 1` / `filter` / `mask` / `clip-path` / `mix-blend-mode` / 对应 `will-change` 时，子元素的 `backdrop-filter` 会失效（[MDN backdrop-filter](https://developer.mozilla.org/docs/Web/CSS/backdrop-filter)）。
- ambient 容器直接挂在 `body` 下、`#app` 之前（或之后但 z-index 更低），不要放进任何带 `transform` / `opacity` / `filter` 的布局容器 —— 那些属性既会改 `fixed` 的包含块，也会制造新的 backdrop root。
- 容器本身**不设** `background`、`backdrop-filter`、`filter`；所有颜色在子元素上。容器只负责裁切（`overflow: hidden`）。
- 内容层（`#app`）保持透明底，底色仍由 `body` 承担；ambient 只负责“多出来的那点色”。

### 3.2 色团数量与色相关系

- **总数恒为 4**：A 主光 / B 暖沙副光 / C 冷蓝灰副光（三团漂移）+ D 静态底洗。三团在所有档位都挂载；**不存在“低档关掉副光”的分支** —— 关掉后右下/右上两带的档间差会掉到 ~1.2，AM-13 必红。
- **色相只允许两类**：
  1. **主色雾（A）**：`--gosslan-primary` 混 `--ambient-mute` 得到，跟随用户在设置里换的主题色；S 固定 **30%**（单值）。
  2. **副光（B / C）**：B 用**暖沙 `hsl(32 12% 64%)`**（暗色 `hsl(32 12% 26%)`），C 用**冷蓝灰 `#7c93b3`**（暗色 `#5b7fb3`，与主色同色相族）。副光只做配角、只出现在边缘，**与 A 共用同一个 α**。
- **禁止**把 `--gosslan-success` / `--gosslan-warning` / `--gosslan-danger` 放进背景。主题色可以是绿、橙、红、紫任意一档，再叠一个语义色必然撞色；“不撞色”的做法是**不引入语义色相**，而不是去算色相差。
- **色相与档位**：主色 S **固定 30%**（上限 35%，超过按霓虹判红）；A/B/C 三团共用**同一个 α**，四档 **亮 20% / 30% / 40% / 50%、暗 16% / 26% / 36% / 46%**（主旋钮，见 §3.3）。D 团**固定 4%**、不跟档位走（AM-14 中点稳定靠它）。
- **色团彼此不重叠超过 2 层**：四团分配到四侧（见 §3.6 的锚点）；交叠只允许 **A+B 或 A+C**，合成值见 §3.3 的表（亮 T4 最高 **75%**、暗 **71%**），且**只允许出现在边缘留色带**，中央 40%×40% 不得出现（§3.3）。

### 3.3 透明度区间（α 亮 20 / 30 / 40 / 50%，暗 16 / 26 / 36 / 46%）

> **v0.5 边界（用户授权 + 实现口径）**：见文首修订说明。原“α 固定 6% / 7%”与 v0.4 的 15%–40% 均已作废；下面这组数是**下给实现的那组**，文档与实现必须一致。

- **允许区间 15%–50%**（用户原话“可以到 30% 到 50% 的透明度”）。四档 **亮 20% / 30% / 40% / 50%，暗 16% / 26% / 36% / 46%** —— 暗色统一 **-4pp**，不再是与亮色同值。**默认档 = 30%（亮）/ 26%（暗）**（用户 2026-11-05 看过四档图后选定 T2）：看得出颜色，又不压过文字。
- **三个前提必须同时成立**，缺一条就把该档 α 回落一档：
  1. **承载正文的表面一律实色/近乎不透明**：消息气泡、卡片、输入框、列表行的背景 **alpha ≥ 0.95**，正文与色雾之间必须隔一层不透明面（判据 AM-15）。这条是抬高 α 的**交换条件**，不是可选建议。
  2. **直接画在画布上的文字**（空状态、时间戳、分组标题、背景上的说明）在最坏合成底上 **≥4.5:1**；不达标就降该层 α，或给这类文字加局部实色底（判据 AM-16）。
  3. **边缘加权**：中央 40%×40% 保持安静 —— 该区域内**最多 1 团、合成 ≤ 该档 α**；A/B/C 的浓度主要放在四周留色带。

**单团换算与合成值（A/B/C 共用同一个 α；D 固定 4%，不跟档位）：**

| 档位 | 主题 | A/B/C 单团 α | D 底洗（静） | 两团合成峰值（边缘） | 中央 40%×40% |
| --- | --- | --- | --- | --- | --- |
| T1「轻微」 | 亮 | 20% | 4% | 36% | ≤1 团，合成 ≤20% |
| T1「轻微」 | 暗 | 16% | 4% | 29% | ≤1 团，合成 ≤16% |
| **T2「默认」** | 亮 | **30%** | 4% | 51% | ≤1 团，合成 ≤30% |
| **T2「默认」** | 暗 | **26%** | 4% | 45% | ≤1 团，合成 ≤26% |
| T3「增强」 | 亮 | 40% | 4% | 64% | ≤1 团，合成 ≤40% |
| T3「增强」 | 暗 | 36% | 4% | 59% | ≤1 团，合成 ≤36% |
| T4「上限」 | 亮 | 50% | 4% | 75% | ≤1 团，合成 ≤50% |
| T4「上限」 | 暗 | 46% | 4% | 71% | ≤1 团，合成 ≤46% |

- **合成口径是 `1 - (1 - a)(1 - b)`，不是简单相加**（半透明叠半透明会彼此“透”出来）。表里的合成值已按取整后的单团值算好，允许 ±1pp。
- **单点最多叠 2 团**（A+B 或 A+C），亮色 T4 的合成峰值为 **75%**、暗色 **71%**；该峰值**只允许出现在边缘留色带**，中央 40%×40% 内不得出现。
- α 是**最终合成值**（相对色语法里 `/ 40%` 的 α），不再乘第二层 `opacity`；实际实现写在 `radial-gradient` 里。
- **α 越高，画布直绘文字越先失守，暗色最先失守**：亮色 T1/T2 的直绘文字仍有余量；**T3（40%）起必须给直绘文字加局部实色底**；暗色四档一律不要把次级文字直接画在色雾上。这里不写死具体对比度数字 —— 四档定稿后必须用 §7 的 AM-16 实测填表，禁止手算估值上线。
- 玻璃本身是 82%–94% 的白色填充，色雾变浓后玻璃会显得更“奶”；**允许的观感边界是“玻璃后面有色，不是玻璃本身有色”**。

### 3.4 存在感、构图与审美（v0.5）

> v0.6 起 **α 是唯一浓度旋钮**，S 固定 30%、尺寸固定 1.30×、薄纱固定 16%/14%，都不再分档。顺序：α → 构图（边缘留色）。

**① 色团 α（主旋钮）**
四档 **亮 20% / 30% / 40% / 50%、暗 16% / 26% / 36% / 46%**（允许区间 15%–50%，**默认 30% / 26%**）。A/B/C 三团共用同一个 `--ambient-alpha`，D 团固定 4%。**抬高 α 的前提是 §3.3 的三条同时成立**：正文面不透明、画布直绘文字达标、中央边缘加权。任何一条未落地，就把该档 α 回落一档。

**② 色相饱和度 S（固定值）**
色相取自 `--gosslan-primary`，**S = 30%（单值，不再按档位取 16/19/22/25）**。这是用户“要有一点色彩，但不要太浓重”的落点：30% 能看出色相偏向，又不会变成染料。上限 **35%**，超过即视为霓虹/高饱和，判红。

**③ 尺寸 / 覆盖（结构旋钮，不承担分档）**
四档统一 **1.30×**（单一变量 `--ambient-scale`）。尺寸只给色团留“走位空间”，不是用来加浓 —— 加浓只走 α。

**④ 薄纱 base（底层旋钮）**
**亮 16% / 暗 14%**（单一变量 `--ambient-veil`）。α 提高后薄纱**不再跟着涨**（26–30% 的旧值会把整片洗成奶白）：薄纱定整体明度，色团定色相分布，两者别混用。

#### 四档可直接切换的配方（v4，最终由四档图 + 眼睛定）

| 档位 | α（亮 / 暗） | S | 副光 | 尺寸 | 薄纱（亮 / 暗） | 正文承载面 | 画布直绘文字 | 定位 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| T1「轻微」 | 20% / 16% | 30% | B 暖沙 + C 冷蓝灰（同 α） | 1.30× | 16% / 14% | 不透明 ≥0.95 | 直接画，达标 | 几乎只感到“底不是平的” |
| **T2「默认」** | **30% / 26%** | 30% | B 暖沙 + C 冷蓝灰（同 α） | 1.30× | 16% / 14% | 不透明 ≥0.95 | 直接画，达标 | **默认档**（用户选定）：色雾可辨、正文不受影响 |
| T3「增强」 | 40% / 36% | 30% | B 暖沙 + C 冷蓝灰（同 α） | 1.30× | 16% / 14% | 不透明 ≥0.95 | 必须加局部实色底，或换 `--gosslan-text` | 更浓一档，按需切 |
| T4「上限」 | 50% / 46% | 30% | B 暖沙 + C 冷蓝灰（同 α） | 1.30× | 16% / 14% | 不透明 ≥0.95 | 必须加局部实色底 + 边缘加权 | 上限档，不再往上加 |

- **正文承载面**指消息气泡、卡片、输入框、列表行；它们的背景 **alpha ≥0.95** 是硬前提（AM-15）。
- **画布直绘文字**指空状态、时间戳、分组标题、背景上的说明；它们必须实测 ≥4.5:1（AM-16）。表里写“必须加局部实色底”不是风格选择，是安全下限。
- 尺寸固定 1.30×（`74vw × 62vh` 等基准 × `--ambient-scale`），四档不随 α 改尺寸 —— 放大色团会让边缘色带更宽，但档间差只能靠 α 拉开。
- 实现色写法：`hsl(from var(--gosslan-primary) h <S>% 60% / <α>)`（相对色语法）；不支持时退回 `color-mix(in srgb, var(--gosslan-primary) <α>, transparent)`，此时 S 不可控，但 α 与安全前提不变。
- **这套数值以用户眼睛最终确认为准**：文档锁的是 α 区间（15%–50%）、安全前提（AM-15/16）与构图约束；**四档图定稿后回填最终档**（哪一档作为默认、哪一档停用都可能被眼睛推翻）。当前写死的默认 = **T2（30% / 26%）**（2026-11-05 用户看四档图后选定；T1/T3/T4 仍可配置，不删档）。

#### 审美约束（三条，写死）

1. **双色相克制搭配**：主色（A）+ **暖沙 `hsl(32 12% 64%)`（B）**，再加一个与主色**同色相族**的冷蓝灰（C）；**不三色齐上、不用 neon**。B/C 只做配角、只出现在边缘、**与 A 共用同一个 α**（早先“0.40× / 只在 T3/T4”的写法已作废：B/C 取 2/3 α 时，右下/右上带的档间差只有 ~1.2，AM-13 必红）。
2. **大色团、低数量**：3 动 + 1 静。**不靠加团提存在感**（加团会打乱“边缘留色”的构图，也破 §4 的层数上限）。
3. **边缘留色、中心留白**：中央 40%×40% 保持安静，内容区像“浮在色雾上”，不是“泡在染料里”；**禁止色团路径穿过正文正中**（判据 AM-14 的中点稳定性 + AM-13 的动团带采样共同守住）。

#### 升级顺序（写死，不许换顺序）

1. **先抬 α**：亮 20% → 30% → 40% → 50%（暗色全程 -4pp），每次只动一档，并且先确认 §3.3 三条前提已落地。
2. **再调构图**：中央 40%×40% 保持安静、边缘留色；空间不够时先收窄色团（改 `clamp()` 基准），仍不靠缩 α 换构图。
3. **副光始终在线**：B 暖沙 + C 冷蓝灰，四档都挂载；`--gosslan-success` / `--gosslan-warning` / `--gosslan-danger` 依旧**禁止**入背景。
4. **到 T4 50%（暗 46%）就停**：再想要更浓，先回来确认“正文面不透明 + 画布文字达标”是否真的成立，而不是继续加 α。
5. **S 固定 30%，不参与升级**：想动 S 必须重跑 AM-15/AM-16；S 越过 35% 直接判红。

#### 明确禁止

- ⛔ **把色团、薄纱或背景的 α 抬到 50% 以上**：越过这条，色雾就变成染色块，玻璃会像“糊了一层奶”，而且画布直绘文字必然失守。
- ⛔ **用半透明正文面换来更浓的色雾**：消息气泡 / 卡片 / 输入框 / 列表行背景 alpha <0.95 即判红（AM-15）—— 正文必须坐在实色面上。
- ⛔ **让色团穿过正文正中**：中央 40%×40% 只允许留白（≤1 团、合成 ≤ 该档 α）。
- ⛔ **霓虹 / 高饱和 / 三色齐上**：S > 35%、或同时出现三个以上色相，都按“撞色”判红。
- ⛔ **在 T1/T2 启用第二色相**：低两档只允许主色 + 底洗，加第二色相即判构图违规。

### 3.5 周期、缓动与位移

| 色团 | 周期 | 缓动 | 方向 | 位移（起 → 止） | 缩放 |
| --- | --- | --- | --- | --- | --- |
| A 主光 | 72s | `ease-in-out` + `alternate` | 右下 → 左上 | `translate3d(0, 0, 0)` → `(3vmax, 2vmax, 0)` | 1.00 → 1.05 |
| B 副光 | 96s | 同上 | 左上 → 右下 | `(2.5vmax, 2vmax, 0)` → `(0, 0, 0)` | 1.04 → 1.00 |
| C 第二色相 | 120s | 同上 | 纵向为主 | `(0, 2vmax, 0)` → `(-2vmax, 1vmax, 0)` | 1.00 → 1.03 |
| D 底洗 | — | — | — | 静止 | 1.00 |

- **B/C 副光四档都在**：常驻动画数恒为 3。采样与判据都按同一条动团带比，不存在“低档右上带是空白”的例外。

- **必须 `alternate`**：单一方向的 `infinite` 会在 72s 处出现一次硬跳；`alternate` 让端点速度归零，接缝不可见。
- **负延迟错相**：`animation-delay: -18s / -42s / -66s`。不要三个都从 0 开始 —— 同相起跑会在前几秒叠成一次“集体呼吸”。
- **位移上限 3vmax**：再大就从“环境”变成“背景在晃”。缩放上限 1.05，超过会让预栅格化的渐变出现轻微软化（可接受），再大就会看出像素。
- **不允许旋转**：低对比团块的旋转在视觉上不可见，只会白增合成开销。
- **不允许动画 `background-position`**：这是最像“漂移”的写法，但它每帧重绘整层，是本方案的**头号禁止项**（见 §4）。

### 3.6 基准尺寸、锚点与颜色

下表是**基准尺寸与锚点**；四档统一 `1.30×`（`--ambient-scale`），锚点（中心）不变。颜色里的 `S` 固定 **30%**，`α` 取 `var(--ambient-alpha)`（A/B/C 同一个值，暗色 -4pp），D 固定 4%。**B/C 副光四档都在**。

| 色团 | 基准尺寸 | 锚点（中心） | 颜色 |
| --- | --- | --- | --- |
| A 主光 | 74vw × 62vh | 6% -12% | `var(--ambient-tint)`（`--gosslan-primary` 混 `--ambient-mute`，S 30%）→ 70% 处透明 |
| B 暖沙 | 68vw × 58vh | 100% 100% | `var(--ambient-warm)`（`hsl(32 12% 64%)`，暗 `hsl(32 12% 26%)`）→ 72% 处透明 |
| C 冷蓝灰 | 56vw × 48vh | 88% 18% | `var(--ambient-tint-cold)`（亮 `#7c93b3` / 暗 `#5b7fb3`）→ 72% 处透明 |
| D 底洗 | 84vw × 72vh | 40% 55% | 同 A 的 tint，**固定 4%**（`--ambient-alpha-d`）→ 75% 处透明 |

锚点写的是**元素左上角**，四团都有 `translate(-50%, -50%)` 把中心拉回锚点 —— B 过去写成 `106% / 108%`、又漏了居中，整团落在视口外，是“只有 A 一团在动”的真因。默认值是 **T2（亮色）**：A/B/C 30%、D 4%；切档只改 `--ambient-alpha`（暗色 26%），尺寸、薄纱、锚点都不动。

> 说明：`hsl(from <color> h s l)` 是 CSS Color 5 的相对色语法，用于把主题色的**色相**保留、只替换 S/L。若目标 WebView 不支持，退回 `color-mix(in srgb, var(--gosslan-primary) <α>, transparent)`：α 与安全前提仍然成立，只是 S 不可控（此时四档靠 α、尺寸与薄纱区分）。

### 3.7 细颗粒 noise

- 资产：一张 **96×96** 的灰度 PNG（或同尺寸 SVG `feTurbulence` 预生成后的位图），平铺；亮色 α 3%，暗色 4%。体积目标 ≤3KB。
- 位置：ambient 容器里**最靠内容的一层**，`pointer-events: none`，**不参与动画**。
- 禁止：运行时生成噪点（`repeating-conic-gradient` 叠几十层、canvas 生成）—— 那会在滚动时反复重绘。
- 禁止：`mix-blend-mode`。它会制造新的合成上下文，也会改 backdrop root；普通 `opacity` 已经够用。

### 3.8 按压涟漪（C2）

- 触发：`pointerdown`，只作用于**主按钮**（primary/danger 实底）与**发送键**；列表行、图标按钮、菜单项**不触发**（它们已有底色按压反馈，见 [design-guidelines §11.3.1](../design-guidelines.md)）。
- 形态：从落点扩散的圆，直径 = `max(控件短边, 240px)`，被控件自身的 `overflow: hidden` + 圆角裁切。**不做全屏涟漪层**。
- 参数：`transform: scale(0.55) → scale(1.25)`，`opacity: 0.12 → 0`，560ms，`cubic-bezier(0.2, 0.7, 0.3, 1)`。
- 并发：同一控件最多 1 个，全屏同时最多 2 个；`prefers-reduced-motion` 下完全不出现。
- 结束即移除 DOM（或复用固定 2 个槽位），不保留空闲节点。

## 4. 性能硬线

| # | 硬线 | 判据 | 违反的后果 |
| --- | --- | --- | --- |
| 1 | 动画属性白名单：**只有 `transform` 和 `opacity`** | 每个 `CSSAnimation` 的 `effect.getKeyframes()` 里出现的属性必须 ⊆ `{transform, opacity}` | 动 `filter`/`blur`/`background-position`/`box-shadow`/`width`/`top` 会逐帧重绘，滚动与空闲同时退化；这条没有“少量例外” |
| 2 | **零逐帧 JS**：无 `requestAnimationFrame` 循环、无 `setInterval`、无 canvas/WebGL | 静态扫描 ambient 实现文件中的禁用符号；运行时以空闲 CPU 复核 | 直接破坏“空闲 CPU 0.09% / 无 rAF 长驻”的实测基线 |
| 3 | **预栅格化**：渐变与柔化在 CSS 里一次画好，运行时不做 `filter` / `backdrop-filter` | ambient 容器与其子元素上不出现 `filter`、`backdrop-filter` | 全屏 `backdrop-filter` 是 WebKit 内存暴涨（bug 328065）与掉帧的典型来源 |
| 4 | **隐藏暂停**：`document.hidden === true` 时所有 ambient 动画 `paused` | 钉住 `document.hidden` 后 200ms 内运行中动画数 = 0 | 后台继续跑动画会烧电，也会让长空闲 CPU 判据变红 |
| 5 | **减少动态效果 = 冻结**：`prefers-reduced-motion: reduce` 下 `animation: none`，停在初始帧 | 运行动画数 = 0，且 `transform` 等于 0% 帧矩阵 | 只把时长拉长（如 30s）仍属“在动”，必须判红 |
| 6 | **预算**：空闲 CPU <1%、3s 空闲 ≤600ms、滚动 p50 ≤ 17ms、长帧 ≤10、帧最大 ≤600ms | 复用 `check-ui-runtime.mjs` 的 perf 段与长空闲段 | 任一超线即回退到静态（见 §5） |
| 7 | **层数**：常驻动画元素 ≤3（上限 4）；动画合成层 ≤3，静态绘制层（薄纱/底洗/颗粒）≤3 且不参与合成 | DOM 计数 + `getAnimations` 计数 | 合成层过多会挤占 GPU 内存，低端机直接掉帧 |

补充约束：

- `will-change: transform` **只写在 3 个漂移团上**，不写在容器、不写在静态团；动画结束/关闭时移除。
- 容器加 `contain: layout paint`（可选 `strict`），把它和内容层的布局/绘制隔离。
- 三个团的 `animation` 必须挂在**同一个容器内的叶子节点**上，不要让容器的 `opacity` 参与动画（会整层重合成并可能影响上层玻璃的采样）。

## 5. 降级与开关

### 5.1 系统偏好降级

| 条件 | 行为 | 依据 |
| --- | --- | --- |
| `prefers-reduced-motion: reduce` | **冻结**：`animation: none`，保留静态色雾（停在初始帧） | 用户要求“少动”，不是“动慢一点” |
| `prefers-reduced-transparency: reduce` | **能力闸**：档位固定落 `off`（`data-ambient="off"` → 整层隐藏），设置页显示为关、两档都不可选，并写明原因；**不写库**（2026-11-08） | 用户口径：能力放不出效果时，给一个"开着却看不到"的开关等于误导 |
| `prefers-contrast: more` | 同“整层隐藏” | 背景带色会让正文对比度随位置漂移 |
| `forced-colors: active` | 整层隐藏 | 系统强制配色下不引入自绘颜色 |
| 窗口 `document.hidden` | `animation-play-state: paused`（不断点、不重建） | 恢复时从原相位继续，避免“回来突然跳一下” |

### 5.2 低端设备

判定（任意一条命中即降为“静态色雾”，不做漂移）：

- `navigator.hardwareConcurrency <= 4`；
- `navigator.deviceMemory <= 4`（Safari 不提供，缺省视为未知，不降级）；
- Android WebView（`userAgent` 含 `; wv`）；
- 视口宽度 < 480px（竖屏手机）：只保留 3 团，且去掉底洗。
- 视口宽度 ≤ 767px（手机 / 小平板，2026-11-06 阶段 5 裁决）：只保留 A/B 两团
  （C 冷团与 D 底洗隐藏），且漂移**冻结到初始帧**（速度降一档到 0）——省电优先，
  色雾保留、不整体降饱和、不隐藏整层。与 `style.css` 的手机竖屏块同值（`md` = 767px）。

**不引入运行时探测器。** 不写“每 30s 采样 CPU、超线自动关”的循环 —— 那本身就是一个常驻定时器，和硬线 2 冲突。低端判定只在启动时做一次，结果写进 `html[data-ambient]`。

### 5.3 与 `html.ambient` 合并成一个设置项

现状：`html.ambient` 是一个**开发者开关**（[style.css](../../src/style.css#L505-L513)），默认关闭，没有 UI。新方案把它变成**用户可见的唯一开关**，内部三态：

| `html[data-ambient]` | 表现 | 谁会拿到 |
| --- | --- | --- |
| `off` | 纯平色（`--gosslan-app-bg`） | 用户关闭；`reduced-transparency` / `contrast` / `forced-colors` |
| `static` | 静态色雾（当前 `html.ambient` 的两团） | 低端设备、小屏、用户选择“静止” |
| `drift` | 3 团漂移 + 颗粒 + 涟漪 | 用户开启（推荐档） |

- **用户只看到两个选项**：`关闭` / `缓慢流动`。`static` 是自动降级档，不单独暴露，避免设置里出现第三个“看起来一样”的选项。
- **放哪**：设置 › 外观（[AppearanceSection.vue](../../src/components/settings/AppearanceSection.vue)），作为「显示模式 / 主题色 / 字体」之后的第四行，复用 `SettingsToggle.vue` + `SettingsRow.vue`。
- **叫什么**：`背景动效`（英文 `Ambient motion`）。副标题写清代价与降级：「极慢的柔光漂移，不影响操作；系统开启“减少动态效果”或低电量模式下自动静止」。
- **默认值**：这是全局观感改动，默认值需要用户点头（见 §9）。在点头前保持 `off`，与现状一致。
- **i18n**：实现时必须中英各一套键（`settings.appearance.ambient.*`），并登记进 `DYNAMIC_PREFIX_WHITELIST` 之外的真实引用面；删除旧键时同提交删干净。
- `html.ambient` 类可以保留为 `static` 的兼容别名，但**不再有新代码写这个类名**，只由设置/降级逻辑写 `data-ambient`。

## 6. 实现骨架建议

### 6.3 同屏动画层数上限

| 类别 | 上限 | 说明 |
| --- | --- | --- |
| 常驻漂移色雾 | 3（硬上限 4） | 每个都是一个合成层 |
| 薄纱 + 静态底洗 + 颗粒 | 3（不合成、不运动） | 不进入 `getAnimations` |
| 按压涟漪 | 2（瞬时） | 560ms 后必须移除 |
| 全局空闲动画预算 | 上线前基线 + 3 | 用基线棘轮判，不把既有动画算到 ambient 头上 |

**不要用 `@property` 动画渐变停点**：即使 `--angle` 是数字、可插值，动画它仍然每帧重绘整层渐变，`getKeyframes()` 里也看不到 `transform`/`opacity` —— 属于硬线 1 的实质违反，必须判红。

### 6.4 三层优先级 + 能力闸（2026-11-08 修订）

一台 Windows 机器的读数是 `prefers-reduced-motion: off`、`prefers-reduced-transparency: on`、
`html[data-ambient]: drift`，雾却整层看不见。2026-11-07 的修法是把透明降级块里的
`.ambient { display: none }` 删掉；2026-11-08 用户重新拍板为**显式能力闸**：

> 系统层本身禁用时（Windows「透明效果」关闭，或 `backdrop-filter` 不可用），设置里的
> 「背景动效」默认关闭、置为不可选并写明原因，避免用户开着却看不到效果。

两次的机制差别是这条的关键：现在不是"CSS 顺手隐藏"，而是 JS 把档位落成 `off`、
设置页同步显示为关且**不可点**，并给出原因。用户看得见"为什么"，原来的选择也还在。

档位只按这四层解析（实现见 [utils/ambient.ts](../../src/utils/ambient.ts) 文件头）：

| 层 | 来源 | 判定 |
| --- | --- | --- |
| 0 | **能力闸** | 系统 `prefers-reduced-transparency: reduce`，或内核同时不支持 `backdrop-filter` / `-webkit-backdrop-filter` → `off`，来源记 `capability` |
| 1 | **软件显式** | 设置里选过「关闭」/「缓慢流动」→ 直接按它，系统偏好不再参与 |
| 2 | **系统** | 用户从未动过开关，且 `prefers-reduced-motion: reduce` → 静态雾（不重播、不位移） |
| 3 | **内置默认** | 前两层都没有 → 流动；低端机 / 视口 < 480 降静态雾 |

- **能力判定只有一个出口**：[utils/ambientCapability.ts](../../src/utils/ambientCapability.ts)。
  `ambient.ts` 不许自己拼透明查询（`AM-13` 盯着），视图层也不许碰 `matchMedia` / `CSS.supports`（护栏 ㉟）。
  `backdrop-filter` 必须同时问 `-webkit-` 前缀，与 `style.css` 的
  `@supports not ((backdrop-filter) or (-webkit-backdrop-filter))` 同口径。
- **"用户主动选过"与"能力不支持"必须分得开**：能力不可用时只改**显示值与 DOM 档位**，
  存储里的显式值一个字不动；能力恢复后原样回到用户那一档。设置页置灰 + 原因文案由
  `ambientCapability.reason` 驱动，不把"能力默认"写进设置。
- **"没设过"与"设成了默认值"同样要分得开**：存储键只有一个，`readStoredAmbientRaw()` 返回
  `null` 才表示没设过；设置页显示用的 `readStoredAmbient()` 会把系统偏好折算成默认值，
  两者不能合并（合并后用户永远无法用软件开关覆盖系统偏好）。
- **显式「流动」要能压过系统 reduce**：只靠 CSS 的 `@media (prefers-reduced-motion: reduce)` 做不到，
  所以 `ambient.ts` 同时写 `html[data-ambient-motion="force"]`，冻结块写成
  `html:not([data-ambient-motion="force"]) .ambient-blob { animation: none }`。
  `force` 按**实际模式**写（`res.mode === "drift"`）：能力闸把档位落成 `off`、低端机落成
  `static` 时写 `force`，只会让诊断面板把"能力关掉"错报成"软件压过系统"。涟漪不在此列 ——
  它是交互反馈，不属于背景氛围。

**采样区定义：动团带，不是中点。**

- 画面正中由**静态 D 团**覆盖（旧配置实测叠成约 **42% 的 plateau**；新 α 下该 plateau 随档位变化，但 D 团**始终不移动**）。A/B/C 三团的位移上限是 3vmax（§3.5），**走不到中点** —— 在中点测，量到的是 D 团，而不是正在被调的 A/B/C 团。实测证据（旧配置）：中点 64×64 的三档差只有 **0.08–0.10 色阶**，ΔE00 远低于任何可用阈值。
- 动团带分**两个子采样区**（2026-11-05 修订；用一个点同时判两条，结构上必有一条测不到）：
  1. **CORE（档间用）** —— 色团 42% plateau 内，各 64×64。那里梯度是平的、α 差分最大：
     A `(6%, 0)`、C `(88%, 18%)`、B `(98%, 96%)`（分数相对 1280×760 夹具，B/C 落在 plateau 内）。
  2. **EDGE（动感用）** —— 色团径向 **56%**（42%→72% 的淡出环上），各 64×64，取色团**朝位移方向**的一侧：
     A `(27.6%, 4.2%)`、C `(73.8%, 9.6%)`、B `(85.4%, 93.3%)`。在 plateau 上位移不改变 α（实测 c 带只有 0.01），必须落在环上。
- **三带全取，不分档**：B/C 副光四档都在，不存在“低档右上带是空白”的例外。
- 若不便逐团定位，退化为「**排除中央 40% × 40% 后的环形带**」，按 40px 网格采点求平均。两种口径都必须在报告里写清用的是哪一种。

**同相位：不同相位比较 = 测相位差，不是测配方差。**

- 采样前把所有 `.ambient-blob` 的 `animation-delay` 临时归零（量具期加 `.ambient-freeze { animation-delay: 0s !important }`）。
- 再逐项冻结到同一时刻（`t` 取 0 或 20000 ms）：

```js
const blobs = document.querySelectorAll(".ambient-blob");
const t = 0; // 或 20000
blobs.forEach((el) =>
  el.getAnimations().forEach((a) => {
    a.pause();
    a.currentTime = t;
  })
);
```

- 四档比较必须**同一个 `t`、同一视口尺寸、同一 devicePixelRatio、同一主题色**；`t=0` 与 `t=+20s` 是唯一允许变化的量，且只在同一档内比较。
- 冻结只属于量具，**不写进生产 CSS**。

**两条判据的含义。**

- 档间 **ΔE00 ≥ 1.5**：并排能看出“换了档”，对应设置页切换后的可感知。
- 同档 **`t=0` → `t=+20s`，ΔE00 ≥ 1.0**：看得出“它在动”。这一条比档间差更接近用户感受 —— 档间拉得再开，只要静止看不出动，背景动态就不成立。
- ΔE00 阈值：1.0 是理论可辨下限，1.5 才“并排一眼看出”，3.0 已是“明显换了底色”。档位差异主要由 **α 与尺寸** 承担（α 四档亮 20/30/40/50%、暗 16/26/36/46%，S 固定 30%）；若实测不过，按 §3.4 的升级顺序走：先抬 α、再扩尺寸（B/C 副光四档常驻同 α，不靠加色相）。

**正文安全（v0.4 新增，是抬高 α 的交换条件）。**

- **AM-15 的检查清单**：消息气泡（含文件/代码/卡片气泡）、通用卡面、输入框与输入卡、会话列表行。它们各自容器的 `background-color` alpha 必须 ≥0.95；`--gosslan-card` 这类主题变量要解析成实际 rgba 再判，不许只看变量名。
- **AM-16 的检查清单**：空状态（无会话/无消息/搜索无结果）的标题与说明、消息时间戳与日期分隔、会话分组标题、背景上的快捷键提示。逐个记录“文字色 + 该点最坏合成底 + 对比度”，四项缺一即视为未验证。
- 两份清单都要进 `--only=ambient` 的产物；**任一条不达标，就把该档 α 回落一档**，而不是去改阈值。

### 7.2 反例自证（门禁必须能红）

九条 fixture 必须真实跑出 FAIL，否则视为门禁空转：

1. **属性白名单**：把 `ambient-drift-a` 的某帧从 `transform` 改成 `filter: blur(24px)` ⇒ AM-03 红，并打印违规属性名。
2. **数量上限**：DOM 里多加一个 `.ambient-blob` ⇒ AM-01 / AM-02 红。
3. **隐藏暂停**：注释掉 `visibilitychange` 监听 ⇒ AM-05 红（running 数仍为 3）。
4. **档位不可辨**：把三档退化为 α 4% / 6% / 8%（即 §3.3 实测的旧做法）⇒ AM-13 判据 ① 红（平均通道差 0.42 色阶、档间 ΔE00 <0.5）。
5. **冻结而非减速**：把 reduce 块改成只调 `animation-duration` ⇒ AM-06 红。
6. **中点采样（已知必然失败）**：把 AM-13 的采样区改回画面正中 64×64 ⇒ 实测三档差只有 **0.08–0.10 色阶**、ΔE00 远低于 1.5 ⇒ 红。这条专门证明“采样区一退回中点，门禁就失效”；修法是**改采样区**，不是调阈值 —— 在中点量到的是静态 D 团，等于在“调 A 团”的地方测“D 团”。
7. **同相位缺失**：保留各自的 `animation-delay: -18s / -42s / -66s` 直接比较 ⇒ 测到的是相位差，同一配方也能“测出”档差 ⇒ 必须红；量具需断言三档冻结在**同一个** `currentTime`。
8. **正文面半透明**：把气泡底改成 `rgba(255,255,255,0.7)`（那种“为了更浓色雾”的常见做法）⇒ AM-15 红（alpha 0.7 < 0.95）。
9. **画布直绘文字失守**：在 T4（亮 50% / 暗 46%）下把时间戳直接画在动团带上、又不加局部实色底 ⇒ AM-16 红；给同一位置加 alpha 0.95 的局部底后 ⇒ 必须转绿。

### 7.3 人工观感验收

- 静止盯着看 10 秒，**说不出“它在动”**，但两帧对比能看出位置差；
- 同屏阅读正文时，注意力不被边缘光团拉走（“柔和不喧宾夺主”的主观对应项）；
- 相隔 30 秒截两帧，像素差 >2/255 的比例 ≤5%（“极慢”的可量化近似）；
- 亮/暗切换时，构图不跳、不换锚点与尺寸，只换色相亮度、S 与薄纱 base。

| 背景动效 | 无。`html.ambient` 是静态两团 `radial-gradient`，默认关闭 | 3 团 CSS 漂移 + 颗粒 + 按压涟漪，按 `data-ambient` 三态 |
| 用户开关 | 无 UI，只能改 DOM 类名 | 设置 › 外观 › 「背景动效」 |
| 降级 | `prefers-reduced-transparency` 只作用于玻璃（[style.css L1828](../../src/style.css#L1828)），没有背景层的降级 | ambient 整层隐藏 + reduce 冻结 + 低端静止 |
| 暂停 | 静态背景无需暂停 | `visibilitychange` 暂停/续播 |
| 存在感 | 三档只在 α 上试过（4% / 6% / 8%），实测平均通道差 0.42 色阶，肉眼不可分；用户反馈“还是太浅、饱和度偏低” | α 四档亮 20% / 30% / 40% / 50%、暗 16% / 26% / 36% / 46%（允许 15%–50%，默认 30% / 26%），S 固定 30%，B/C 副光四档常驻同 α；前提是正文面 alpha ≥0.95、画布直绘文字 ≥4.5:1、中央边缘加权。AM-13 在动团带内判档间 ΔE00 ≥1.5、同档 20s 动感 ≥1.0，AM-14 中点 ≤0.5，AM-15/16 守正文安全 |
| 量具 | perf 段有滚动/空闲读数，没有动画属性与层数判据 | 新增 `--only=ambient` 与 AM-01…AM-16 |
| 颗粒 | 无 | 96×96 PNG，α 3%/4%，静态 |

升级顺序建议：先落 CSS 骨架与三态开关（不动任何组件）→ 接 `visibilitychange` → 加 `--only=ambient` 判据与九条反例 → 最后再把涟漪接到主按钮（会碰组件，单独一个提交）。

## 9. `needs-user-signoff`

1. **默认值**：新方案默认 `开启` 还是继续 `关闭`？（本文建议先关闭，用户点头后再改默认）。
2. **设置项名称与位置**：「设置 › 外观 › 背景动效（Ambient motion）」，两个可见选项 `关闭 / 缓慢流动`。
3. **存在感档位**：T1「轻微」/ T2「默认」/ T3「增强」/ T4「上限」四档，**默认 T2（亮 30% / 暗 26%）**。四档 α 亮 20/30/40/50%、暗 16/26/36/46%，S 固定 30%。**已由用户 2026-11-05 看四档图确认（选定 T2）**；文档锁 α 区间（15%–50%）、安全前提（AM-15/16）、构图约束与 ΔE 门槛（档间 ≥1.5、动感 ≥1.0）。

5. **噪点资产**：允许新增一张 ≤3KB 的 96×96 PNG（打包进前端资产），还是要求纯 CSS（纯 CSS 方案会增加重绘，不建议）。

## 11. 平台媒体查询对照（2026-11-07）

用户反馈「Windows 和 macOS 背景动效不一样」。同一份 CSS 在两套 WebView 里会分叉的**只有**下面
这几个查询与能力探测；`--ambient-*` 让渡给系统设置的档位也由它们决定。诊断入口：
**网络诊断 › 背景动效读数 › 复制诊断信息**（实现：`utils/ambientProbe.ts`，只取样不判断）。

| 查询 / 探测 | 改动什么 | macOS（WKWebView） | Windows（WebView2） | 诊断字段 |
| --- | --- | --- | --- | --- |
| `prefers-reduced-motion: reduce` | 关掉漂移，只留静态色雾 | 跟随「减弱动态效果」 | 跟随「动画效果」开关 | 同名行 |
| `prefers-reduced-transparency: reduce` | 降低薄纱/模糊，正文面更实 | **不生效**（WebKit 未实现） | 跟随「透明效果」开关 | 同名行 |
| `prefers-contrast: more` | 提高分隔线与正文对比 | 仅在辅助功能里开启时 | 跟随「对比度主题」 | 同名行 |
| `forced-colors: active` | 高对比模式下退回系统色 | 基本不触发 | 高对比主题会触发 | 同名行 |
| `pointer: coarse` | 触屏档的密度与点击目标 | 触控板仍为 fine | 触屏设备为 coarse | 同名行 |
| `backdrop-filter` 支持探测 | 不支持时退回纯色面 | 支持（但大面积 blur 有内存代价） | 支持 | `backdrop-filter: supported / unsupported` |
| `<html data-ambient>` | 实际生效档位（off / drift） | 由 `utils/ambient.ts` 写入 | 同左 | `html[data-ambient]` |

判读规则：

1. 两平台 `data-ambient` 不同 ⇒ 先看 `prefers-reduced-motion` / `prefers-reduced-transparency`
   是否有 `on`，那是系统设置让渡，不是缺陷。
2. `data-ambient` 相同但观感不同 ⇒ 看 `backdrop-filter` 与 `devicePixelRatio`：
   Windows 常见 125% / 150% 缩放，薄纱在非整数缩放下更明显。
3. 三项查询都为 `off`、`data-ambient` 也相同，仍然有差异 ⇒ 剩余变量在 WebView 合成器，不在本仓 CSS；
   带上整段复制内容与截图再开单，不要再改 α 口径。
