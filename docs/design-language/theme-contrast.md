# 全局配色与对比度契约（2026-11-08）

本项目的颜色不再是「手挑一版色值」，而是**以主色为种子、在 OKLCH 里求解**：

- 静态数值写在 [src/style.css](../../src/style.css)，是"JS 还没跑"时的首帧；
- 运行时由 [src/utils/themePalette.ts](../../src/utils/themePalette.ts) 现算，`applyTheme` 把与主色相关的
  6 项写到 `<html>`（填充 / hover / active / 前景 / accent-ink / 浅底）；
- 两边必须逐 token 相同 —— [themePalette.test.ts](../../src/utils/themePalette.test.ts) 的「防两份实现漂移」
  一条会逐项比对，手改其中一边就会红。

改色的唯一合法流程：**改求解器 → `node --experimental-strip-types scripts/dump-theme-tokens.mjs` 生成 CSS
数值 → 跑 `npm test`**。

## 1. 算法

对一颗种子 `#rrggbb`：

1. 转 OKLCH，得到 `L / C / H`。`C < 0.004` 视为灰阶种子（不虚构品牌色相）。
2. 中性面（画布/列表/面板/卡片/输入框/边框）只继承 `2% × C`、夹在 `[0.002, 0.006]` 的彩度：
   换主色时背景极轻微偏色，但不会变成彩色玻璃，也不影响文字对比度（对比度只由 L 决定）。
3. 主色填充沿 **L 轴**取档，色相与彩度（上限 0.20）保持种子：
   - 亮色：从 L=0.68 往下找**最浅且白字达标**的一档，再与种子自身 L 取较小者（深种子保持深）；
   - 暗色：从 L=0.68 往上找**最暗且深墨达标**的一档，再与种子自身 L 取较大者（浅种子保持浅）。
4. `hover / active` 是"更强调"各走一档，不是常数：亮色 `L−0.035 / L−0.070`（更深），
   暗色 `L+0.035 / L+0.070`（更亮）。
5. 中性文字（正文 / 次文本 / 占位 / rail）在最差的那层面底上求解：亮色用卡片底（最暗），
   暗色用面板底 / 胶囊底（最亮）。
6. 语义色（危险 hue 20 / 警告 65 / 成功 160）色相恒定，只沿 L 轴取档，不跟主色走。

## 2. 阈值

每一档都过**双约束**：APCA 0.1.9 的 `|Lc|` **并且** WCAG 比值。只按 APCA 派生会让仓库既有的
WCAG 护栏当场变红（APCA 45 换算成 WCAG 只有 2.3~4.2）。

| 档位 | APCA 下限 | 求解目标 | WCAG 下限 | 用途 |
|---|---|---|---|---|
| 正文 | 85 | 89 | 7 | 消息正文、列表标题 |
| 次文本 | 70 | 72 | 4.55 | 摘要、说明、辅助图标 |
| 弱文本 | 60 | 64 | 4.68 | 占位符 |
| 按钮 | 75 | 78 | 4.55 | 实底按钮上的文字 |
| 图标 | 45 | 47 | 3.02 | 状态点、边框、轨道 |

阈值常量在 `themePalette.ts` 的 `APCA_LIMITS`，测试里有"阈值钉死"一条：调低就红。

## 3. 与 Apple HIG / Material 3 的取舍

| 议题 | 结论 |
|---|---|
| 系统色 / 语义色 | 危险/警告/成功仍是语义 token，组件不写死色阶；但色值由求解器按底求解，不照抄系统色（系统红白字只有 3.55）。 |
| 暗色抬升靠"更亮的表面"而非描边 | 照做：暗色面板/卡片的 L 越高越"靠近用户"，不靠描边拉层级。 |
| Increase Contrast / Reduce Transparency | 高对比档沿用既有 `prefers-contrast` 覆盖；玻璃的三条 fallback 改成别名（`var(--gosslan-list/panel)`），不再硬编近似色。 |
| 正文 / 次要文字层级 | 照做：两档由求解器分别钉在 89 / 72 Lc，且次要档在暗色**比占位符亮**（占位符不跟真输入值同亮度）。 |
| M3 tonal palette / on-color | 取思路不取色板：亮色填充 = 压深承白字，暗色填充 = 提亮换深墨（等价 tone-80）。 |
| M3 暗色状态色（浅底深字） | **偏离**：用户拍板危险色保留深底白字。代价是它与暗面板只有 ~2.6:1（"白字 ≥4.5"与"填充 vs 面板 ≥3"在暗色不可同时成立）。 |
| M3 暗色 warning/success 实底 | 这两档上面压的是 `--gosslan-on-primary`（暗色=深墨），深底 + 深墨会看不见 ⇒ 只能提亮填充（与 M3 同向）。 |
| 开源库 | **不引入**。只需要 OKLCH 换算 + APCA + WCAG 三件事：`culori` 约 40KB（含 clamp/chroma 全套色空间），`material-color-utilities` 的 HCT 与 OKLCH 不同空间、换过去要重算全部阈值。本文件里的实现 ~200 行、零依赖、可被测试逐档验收。 |

## 4. 已知偏差

- 暗色 `--gosslan-danger` #cf3546 对暗面板 #2e2f31 只有 **2.72:1**（白字压它 4.94 过 AA）——
  这是用户 2026-11-08 拍板保留"深底白字"的接受项，不是漏校。
- 暗色 warning/success 的**文字档**取 `#ffc690 / #56eba7` 一类浅色，视觉上比系统色粉一档 —— 换来在小字号下稳过 4.5。
- 轨道（`--gosslan-toggle-off`）只判 WCAG 3.0 两维（vs 面板、白滑块 vs 轨道），不挂 APCA 45：
  暗色面板上两者数学上不可同时成立。
