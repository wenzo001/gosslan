### 2.3 安卓端「列表→聊天」转场残余（根因已定位，已落码并复验）

**现象原话**（用户 2026-11-09，安卓端）：「从那个信息列表点到那个聊天界面，它那个信息列表的
那个界面会有残余……跳转的过程中和跳转最后……那个信息列表还会在界面上的底部残余一下，然后才
消失，就是感觉像卡了一样。」

**复现路径**：安卓（移动档；本机用 390×844 + 移动 UA 在 headless Chromium 里复现）→ 会话列表
→ 点任一会话 → 看进入聊天页那 ~280ms 的转场。

**已排除的方向及证据**：

- **静止终态穿透**：`node scripts/check-ui-runtime.mjs --only=bleed` 在六档宽度
  `[1280,900,768,640,430,390]` × 亮/暗 × frost 开/关 = **27 格全绿**。说明"停下之后列表还从薄纱
  下透出来"那个旧缺陷已经修掉，问题只发生在**转场过程**。
- **路由 / `<Transition>` 组件**：这条转场不是路由切换，也没有 `<Transition>`；是同一路由内
  `mobileView: 'list' | 'chat'` 驱动的 CSS transform 平移。改路由或加 `appear` 不解决问题。

**转场帧逐帧读数**（`/tmp/gosslan-pane/trace.mjs`，390×844，真 `ResponsiveLayout` + 真
store/router，点击后开始计时，54 帧采样）：

| t (ms) | 列表 `aside` visibility | aside transform x | 聊天列 `main` transform x |
|---|---|---|---|
| 21 | visible | −17.3px | +332.3px |
| 105 | visible | −104.6px | +41.2px |
| 138 | visible | −110.9px | +20.3px |
| 171 | visible | −114.1px | +9.7px |
| 255 | visible | −116.9px | +0.5px |
| 288 | **hidden** | −117px | 0 |
| 321+ | hidden | −117px | 0 |

读数含义：`aside` 是 `w-full`（整屏宽 390px），终点只平移 −117px（= 30% × 390）⇒ **右侧 273px
一直压在聊天列（z-20）下面**；而 `pane-under-chat` 的 `visibility:hidden` 直到 t≈288ms
（280ms 转场结束后的下一帧）才生效。即 **0–288ms 整个转场期间，旧列表的全宽面板都在新页面底下**。

**像素差分**（`/tmp/gosslan-pane/measure3.mjs`：把转场冻结在进度 `e`，截图 A=列表可见 /
B=列表 `visibility:hidden`，只在"被聊天列盖住"的区域逐点比较色阶差）：

| 进度 e | 聊天列左缘 x | 盖住区最大色阶差 | >2 色阶的像素点 |
|---|---|---|---|
| 0.40 | 234px | **174** | 124 / 1360 |
| 0.70 | 117px | **174** | 219 / 2295 |
| 0.95 | 20px | **190** | 297 / 3145 |

**根因**（两条独立证据交叉：逐帧 visibility/transform 轨迹 + 冻结姿态像素差分）：

1. 列表整屏宽、只做 30% 视差平移，右侧 70% 始终在聊天列下方；聊天列是薄纱
   （`--ambient-veil` 亮 0.16 / 暗 0.14）而非不透明底 ⇒ 旧列表整段透出。
2. `pane-under-chat` 用 `transition-delay: var(--gosslan-duration)` 把 `visibility` 推到平移结束
   之后才切，等于**主动延长了透出窗口**。
3. 第二个面：一级 tab 瞬时切换时 TabBar 立刻消失、`.conv-footer-safe` 的 margin 随之变化，
   列表底部（版本号页脚那一行）会在终态再露一下 —— 截图 `/tmp/gosslan-pane/out4/push-040ms.png`
   可见，未单独量化。

**候选修法与同口径读数（已验证，尚未落码）**：列表在移动端按转场进度裁剪到聊天列左缘之外
（`clip-path: inset(0 calc(70% * e) 0 0)`，与 −30% 平移互补）。measure3 同一套量法、同一批
像素点：

| 进度 e | 现状 max / 超阈点 | clip 候选 max / 超阈点 |

### 2.4 移动端多图预览：左右滑动无法上一张/下一张（2026-11-09 17:40 已修并复验）

**现象**（用户 2026-11-09）：「移动端图片预览，多图片预览模式，左右滑动图片没法上一张下一张。」

**真因（探针实读，两条独立证据）**：不是黑边、也不是阈值。`ImageLightbox.vue` 里
`pointers` 这张 Map 同时被当成"起点"和"当前位置"用：

- `onPointerMove` 每次都 `pointers.set(e.pointerId, {x: e.clientX, y: e.clientY})`（改成当前点）；
- `onPointerUp` 又 `const start = pointers.get(e.pointerId)` 拿它当起点 ⇒
  `dx = clientX - 最后一次 move 的 clientX = 0` ⇒ `swipeDirection` 永远返回 `null`。
- 只有"按下即抬起、没有任何 move"的手势才碰巧能切图（这也解释了"偶发能切"的观感）。

第二层缺口：四个 pointer 事件只挂在 `<motion.img>` 上，黑边/上下留白根本起不了手势链。

**证据**：临时在产品 `onPointerUp` 里读一次 `{type,dx,dy,dragging,scale,index,count}`，
CDP 触摸滑 120px 时读到 `{"type":"touch","dx":0,"dy":0,...,"index":1,"count":3}`；
而同一事件在 window 捕获层读到的 clientX 是从 195 → 75 的（窗口日志）。

**修法**：

1. 起点单独存 `swipeStart`（只在 pointerdown 写、双指时清空），`onPointerUp` 用它算 dx/dy；
   `pointers` 只留给双指距离与"是否还有手指"。
2. 四个 pointer 事件从 `<motion.img>` 移到 `:ref="setDialogRef"` 的图片区域容器上
   （含左右黑边与上下留白）；img 只保留 `@click.stop` / `@dblclick` / `@contextmenu`。
3. 静态回归：`designGuards.test.ts` 新增一条（起点不得取自 `pointers`、手势必须在容器上），
   并带三条反例（改回 `pointers.get` / 摘掉容器绑定 / 加回 img 都必须红）。
4. 运行时探针：`check-ui-runtime.mjs` 新增 `--only=imgswipe`（9 条判据）。

### 2.15 网络拓扑图（2026-11-10，5.21.0）

用户需求（原话）：「类似 lan 图 / 网络图 / 拓扑图，可视化去中心化网络；一眼看出自己、
直连还是中转、几条、连接方式；哪些是好友；点节点可加好友或看信息，好友信息更全」。
三处口径由用户当场拍板：入口 **我的 → 网络拓扑**；数据 **自中心图 + 中转分组**；
库 **force-graph**。

**数据口径（不许虚构边）**：后端只给「每个节点到本机的最佳链路」（`Peer.link`）与
好友会话的 `get_conv_link`（`path/hop`），**不提供其他节点之间的边**。因此：

- 本机居中；`Peer.link` 为 lan/routed/bluetooth/relay 的节点直连自己；
- `relay` 与「好友会话 hop>0」各挂一个合成中枢（`__hub_relay__` / `__hub_mesh__`），
  节点挂在中枢下 —— 不画「A、B 之间直连」这种没有证据的线；
- 非好友没有会话，因此 Mesh 分组只可能来自好友会话的 hop。

**交互**：好友 = 蓝色实心、非好友 = 灰色、中枢 = 琥珀空心；直连边按链路着色/线型，
中转边琥珀虚线 + 跳数。点节点 → 详情卡（桌面右栏 / 窄屏底部卡）：好友给链路/延迟/设备/
版本 +「发消息」；非好友只给「加好友」，对方已先发申请时按钮改「同意申请」并真的走
`respondRequest`（不会两边互相申请）。

**性能/打包**：`ResponsiveLayout` 用 `defineAsyncComponent`，Vite `manualChunks` 单列
`topology` chunk。2026-11-10 同机 `npm run build`：`topology` 168.70 kB / gzip 57.65，
`NetworkTopology` 14.56 kB / gzip 5.09，首屏 vendor 480.69 / gzip 150.12（未增加）。
依赖登记进 `docs/architecture/open-source-replacement-matrix.md` §3。

**验证**：`npm test` **2040/2040**；`node scripts/check-ui-runtime.mjs --only=topology`
**6/6**（Canvas 真落笔 ink≥50 / 画布钉在真图区 / 四项计数 / 图例五行 / 力导向落点 /
点节点开卡且动作键与身份一致），连续 7 趟全绿。

**点击为什么不用 force-graph 自带的 `onNodeClick`**：那套命中走一块 **800ms 节流**的

`screen2GraphCoords` + 节点当前坐标做命中（拖动 >6px 不算点击），并**摘掉库的
`onNodeClick`/`onBackgroundClick`**；探针也就不用再和那块影子画布赛跑。

## 4. 接手必须知道的坑

1. **`Version-Bump:` 只认 `patch|minor|major|none`**（`scripts/semver.mjs:303`）。写成版本号
   （如 `Version-Bump: 5.20.4`）等于没声明。
2. **Change Budget 判据 3** 是「领域窗口内修补形状提交 ≥ 3 次即红」。CI 按
   `before..sha` 取范围；本地按 `origin/<branch>..HEAD` → `HEAD~1..HEAD` 依次取第一个非空范围。
   历史上「本地范围为空 ⇒ 误判通过」的口子已于 2026-11-07 收掉：零覆盖现在直接 exit 1
   （见 `scripts/verify.mjs` 该步注释），不要再按旧说法理解。
3. **一次性发多个补丁号会撞号**：定号前先 `git ls-remote --tags origin` 确认远端没有该 tag；
   已发布的 tag **尽量不重打**（重推会重跑六路 + sync-gitee）。
4. **`check-doc-citations.mjs` 的口径已变**：2026-11-07 起会把「新增但还没 `git add` 的
   `.md`」也算进来（`scripts/check-doc-citations.mjs:250`）。旧说法「只扫 `git ls-files`、
