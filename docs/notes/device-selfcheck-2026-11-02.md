# 设备自查清单（2026-11-02）

> 目标：点几下就能给出结果。每步只写「做什么 / 应该看到什么 / 怎么反馈」。
> 有问题就截图 + 附日志路径；没问题回一句「第 N 步通过」即可。

## Mac

1. **双实例启动**：正常打开应用；再开一份时用 `--instance 2`（或设 `GOSSLAN_INSTANCE=2`）。
   预期：两份都能进主界面，设备名/会话不串。
2. **加好友**：A 搜索到 B → 发送申请；B 点同意。
   预期：两边「新的朋友」清空、好友列表各出现对方、在线点变绿。
3. **单聊**：A 发一条文字，B 收到并回复。
   预期：两边气泡顺序正确；A 的消息从「发送中」变「已送达」，B 打开会话后 A 变「已读」。
4. **群**：A 建群拉 B → 发一条群消息 + 一个群文件。
   预期：B 收到消息；群文件在 B 侧能下载/打开；A 的群文件回执显示成员送达。
5. **通知**：把 B 切到后台，A 发一条消息。
   预期：B 出现系统通知；点通知能跳到对应会话。
6. **升级**：设置 → 关于 → 检查更新。
   预期：能查到新版本；下载/安装前有确认；不静默重启。
7. **反馈**：有问题时截图 + 附
   `~/Library/Application Support/com.gosslan.app/logs/gosslan.log` 与
   `gosslan-crash.log`（多实例是 `gosslan-2-*.log`）。

## Windows

1. **启动与日志位置**：打开应用，确认能进主界面。日志在
   `%APPDATA%\com.gosslan.app\logs\gosslan.log`，
   卡死/崩溃现场在同目录 `gosslan-crash.log`（多实例是 `gosslan-2-crash.log`）。
2. **多窗口**：打开设置窗口 → 再打开日志窗口 → 在两个窗口间来回切。
   预期：都能正常显示，不白屏、不永久卡「加载中」。
3. **最小化/切后台**：主窗口最小化 30 秒，再恢复；再切到别的应用 30 秒后回来。
   预期：恢复后消息列表/在线状态正常刷新，不需要重启。
4. **长会话滚动**：打开一个消息较多的会话，连续快速滚到底、再滚回顶。
   预期：不卡死、不空白、滚动位置合理。
5. **卡死现场**：如果界面无响应，先**不要立刻杀进程**：
   - 任务管理器 → 详细信息 → 找到 `gosslan.exe`，记录 CPU、内存、是否「未响应」；
   - 等 30 秒看是否恢复；恢复/不恢复都记下来；
   - 关闭后把 `logs\gosslan-crash.log` 和 `logs\gosslan.log` 一起发回。
6. **反馈**：附截图/录屏 + 上面两份日志 + 复现步骤（第 2/3/4 步哪一步）。

## Android

1. **安装**：从 Release 下载对应架构的 APK（通常 `arm64-v8a`），允许「安装未知来源」后安装。
   预期：能启动到主界面，不闪退。
2. **权限**：首次进入按提示允许通知；文件收发时按提示允许所选目录/文件访问。
   预期：拒绝通知时应用仍可用，只是不弹系统通知。
3. **收发消息**：与另一台设备互发一条文字。
   预期：两边都能收到；发送方状态从「发送中」到「已送达」。
4. **收发文件**：发一张图片/一个小文件，接收方打开。
   预期：能预览/打开，进度到 100% 后不回落。
5. **通知与后台**：把应用切到后台/锁屏，另一台发消息。
   预期：能收到通知；点通知回到对应会话（受系统省电策略影响时记下机型）。
6. **旋转与返回**：聊天页旋转屏幕；按系统返回键从会话回列表、再回桌面。
   预期：不丢当前会话、不白屏、返回层级正确。
7. **反馈**：附机型/系统版本 + 截图；日志用 `adb logcat -s gosslan` 抓取后发回。
