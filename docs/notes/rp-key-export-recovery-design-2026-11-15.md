# RP 绑定密钥的导出与恢复（设计稿）

> 日期：2026-11-15
> 状态：**已按本文实现（客户端），平台密钥库迁移仍未做**。用户 2026-11-15 裁决「设计一个导出恢复」；
> 同日落地：`src-tauri/src/rp_key_backup.rs`（格式/加密/冲突判定）+ `src-tauri/src/commands/rp_key_backup.rs`
> （三条命令）+ `src/components/settings/RpKeyBackupSection.vue`（设置 → 第三方接入 →「导出与恢复」；2026-11-17 从「关于」拆出独立 tab）。
> 单测与接线判据见 §10；§9 的**顺序约束仍然有效**（导出先于抹明文 seed，现在导出已可用）。
> 本文保留设计与取舍，实现细节以源码为准。
> 相关：`docs/notes/external-auth-integration-contract-2026-11-14.md` §5（密钥保护）、§11.1（裁决登记）。

## 1. 一句话结论

做**用户主动触发、口令加密、单文件**的绑定包导出/恢复；**不做**自动备份、明文导出、云同步；
**不导出 P2P 身份密钥**。导出后这份文件就是一份可移植的设备凭证 —— RP 无法区分「本机」与
「另一台导入的机器」，这是有意接受的取舍，必须让用户在导出前看见这句话。

## 2. 为什么需要它（与密钥库迁移绑在一起）

现状（2026-11-15）：RP 私钥是 base64(seed) 存在本地 SQLite 的 `rp_device_bindings.secret_key`。
清数据、卸载重装、换机、密钥库迁移中删旧值，都会让绑定**永久丢失**，用户只能到每个 RP 的应用里
重新绑定一次。裁决「上平台密钥库」之后这一点更尖锐：密钥库里的条目会随卸载一起消失。

三条路，取舍如下：

| 方案 | 用户代价 | 安全性 | 结论 |
|---|---|---|---|
| A. 什么都不做（重绑） | 每个应用重绑一次 | 最好（凭证永不离开设备） | 必须保留为兜底 |
| B. 导出/恢复（本文） | 记一个口令 + 保管一个文件 | 中（文件可复制；弱口令可离线爆破） | **做**，作为迁移与换机的主要路径 |
| C. RP 侧「用已有账号重新绑定」 | 走一次登录+确认 | 好 | **推荐与 B 并存**，由 RP 实现，客户端不新增东西 |

## 3. 威胁模型（必须先说清）

- **文件即凭证**：拿到文件 + 口令的人，可以在任何机器上对**这些 RP** 伪造断言，直到 RP 侧撤销。
  RP 侧看到的是同一把公钥，**不会**因为来自另一台机器而拒绝。
- **弱口令 = 可离线爆破**：攻击者拿到文件后可本地无限次尝试 ⇒ 必须用内存硬 KDF（§5）+ 强口令提示；
  没有任何"服务端限速"可用。
- **口令不可找回**：没有后门、没有提示问题、没有客服重置。忘记口令等于文件作废（本地绑定仍在）。
- **不导出 P2P 身份密钥**：那是"你是你"的根（聊天签名/解密），与"某个站点信任这台设备"是两件事。
  导出它会把"设备凭证"升级成"人身冒充"，坚决不做（导出包内**逐字节检查**不含该类字段）。
- **导出不扩大信任**：RP 的信任锚仍是那把公钥；导出只是把私钥搬到别处，撤销路径不变。
- **UI 必须显示**：「此文件可在另一台设备上冒充本机登录这些应用；请勿上传网盘/聊天工具」。

## 4. 文件格式 v1（字节级）

固定扩展名 `.gosslankey`，整体单文件。**头部全部作为 AEAD 的 AAD**，防止把 KDF 参数改成弱值后重算。

| 偏移 | 字段 | 长度 | 说明 |
|---|---|---|---|
| 0 | magic | 13 | ASCII `GOSSLAN-RPKEY` |
| 13 | format_version | u16 BE | 当前 `1` |
| 15 | kdf_id | u8 | `1` = Argon2id；其它值整包拒（fail closed） |
| 16 | m_cost_kib | u32 BE | Argon2id 内存（KiB），下限 65536 |
| 20 | t_cost | u32 BE | 迭代次数，下限 3 |
| 24 | p_cost | u8 | 并行度，取值 1 |
| 25 | salt | 16 | CSPRNG |
| 41 | nonce | 24 | XChaCha20-Poly1305 |
| 65 | ciphertext | 余下 | 密文 + 16B tag |

- 算法：`Argon2id(passphrase, salt, m, t, p) → 32B key`，再 `XChaCha20-Poly1305(key, nonce, aad=header[0..65], pt)`。
- 依赖：`chacha20poly1305` 已在依赖树；**需新增 `argon2`（MIT OR Apache-2.0，`src-tauri/deny.toml` 的白名单已含）**。
- 文件权限：Unix `0600`；Windows 走用户目录 ACL（与日志目录同源）。
- 大小上限：8 MiB（防解析 DoS）；绑定条数上限 256。

明文（JSON，序列化顺序固定；解析端不依赖顺序）：

```json
{
  "v": 1,
  "exported_at": 1763200000,
  "app": { "name": "Gosslan", "version": "5.29.0", "os": "macos" },
  "bindings": [
    {
      "rp_origin": "https://acme.example.com",
      "client_id": "acme",
      "display_name": "Acme 控制台",
      "kid": "…base64url(sha256(pubkey))…",
      "public_key": "…base64url 32B…",
      "secret_key": "…base64(std) 32B seed…",
      "pairwise_subject": "…",
      "scopes": "",
      "created_at": 1763000000,
      "status": "active"
    }
  ]
}
```

为什么每个字段都要：`secret_key` 是唯一秘密；`public_key`/`kid`/`pairwise_subject` 用于**导入时自校验**
（由 seed 重算公钥与 kid，不一致就整条拒 —— 防"文件被手工改过"）；`rp_origin`+`client_id` 是主键；
`created_at` 只用于展示（恢复后不伪造 `last_used_at`）。

## 5. 口令与 KDF 参数

- 口令长度 ≥ 12 字符；只做"长度 + 是否明显重复"的弱口令提示，**不做**复杂度强制（强制会催生
  `Password1!` 这类东西）。
- 参数下限：`m=65536 KiB, t=3, p=1`（约 64 MiB 内存）；解析时低于下限直接拒（防降级攻击）。
- 解密失败一律回**同一个**可读错误（"口令错误或文件已损坏"），不区分是 tag 错还是口令错。

## 6. 导出流程（UI + 状态机）

入口：设置 → 第三方接入（2026-11-17 前在「关于」的安全区）→ 已授权应用区块下的「导出…」。状态机：

```text
空闲 → 输入口令（两次，第二次用于确认）→ 选择保存位置 → 写入 → 完成(显示条数)
                    └─ 口令太短/两次不一致 ⇒ 停在输入
                                              └─ 写入失败 ⇒ 明确错误，不留下半截文件（先写 .tmp 再 rename）
```

- 导出内容 = **当前非 `registration_failed` 的本地绑定**；`revoked` 的也导出（标 `revoked`），
  这样恢复后不会"假复活"（§7）。
- 不导出任何 P2P 密钥；导出函数只读 `rp_device_bindings` 的既有列，**不新增表/列**
  （SQLite schema 属 Frozen Core）。
- 完成后提示：文件路径 + "请自行保管，忘记口令无法恢复"。

## 7. 恢复流程（含冲突矩阵）

```text
选择文件 → 输入口令 → 解密+校验 → 预览（逐条结果）→ 用户确认 → 单事务写入 → 汇总
```

逐条判定（冲突**不静默覆盖**）：

| 本地现状 | 文件里的条目 | 结果 |
|---|---|---|
| 无该 (rp_origin, client_id) | active | **新增**（`status=active`） |
| 无该键 | revoked | 新增但保持 `revoked`（用户仍需重新绑定） |
| 有，且 `public_key` 相同 | 任意 | **跳过**（幂等；重复导入同一文件不产生变化） |
| 有，且 `public_key` 不同 | 任意 | **冲突：不写入**，报告"本机已有该应用的另一把密钥" |
| 有，本地 `revoked`，文件 active | active | **拒绝复活**（报告"本机已撤销，需重新绑定"） |
| 任一条自校验失败（kid/公钥对不上） | — | 整包拒（文件被改过） |

- **原子性**：单事务，全成功或全回滚；部分冲突时**其余可导入**，但报告里逐条列明。
- 恢复后 `last_used_at` 保持原值（不知道就以 `created_at` 填），不伪造"刚刚用过"。

## 8. 失败与恢复路径

| 情形 | 用户看到 | 处置 |
|---|---|---|
| 口令错 / 文件损坏 | 口令错误或文件已损坏 | 重试；无次数限制但每次 Argon2id ≈ 数百 ms，天然限速 |
| 格式版本更高 | 此文件由更新版本的小院儿导出 | 提示升级；**不尝试猜格式** |
| KDF 参数低于下限 | 文件已损坏或被篡改 | 拒（防降级） |
| 密钥库不可用（迁移后） | 无法访问系统密钥库 | **不回落到 SQLite 明文**，拒绝并给排查指引 |
| 磁盘满 / 写入中断 | 导出失败 | `.tmp` + rename；失败清理临时文件 |
| 导入中崩溃 | — | 单事务 ⇒ 下次启动看到的是导入前状态 |

## 9. 与密钥库迁移的顺序（这条最关键）

1. **先**上平台密钥库并迁移（`secret_key` 列在新值可用后**逐步废弃**）；
2. **再**提供导出（导出从密钥库读；导出前要求用户手势/系统解锁）；
3. **最后**才允许把 SQLite 里的明文 seed 抹掉。

理由：**导出能力必须先于"删旧值"可用**，否则用户在迁移中途重装就永久失绑、毫无退路。
反过来做（先删再补导出）等于让用户当小白鼠。

## 10. 验收判据（实现时逐条钉）

1. 格式往返：导出 → 导入（另一实例）→ 绑定可用，`kid`/`public_key`/`pairwise_subject` 逐字一致。
2. 错口令：回同一错误码；文件未被破坏。
3. 翻一位字节（header 与 ciphertext 各一处）：**都**解密失败（AAD 覆盖头部）。
4. 降级：把 `m_cost_kib` 改成 1024 重加密 ⇒ 解析端拒。
5. 冲突矩阵 §7 六行逐行有用例（尤其"不覆盖不同公钥"与"不复活 revoked"）。
6. 原子性：第 3 条失败时，前 2 条不得留在库里。
7. 跨平台：macOS 导出的包在 Windows/Android 导入成功（seed 是 32B 原始字节，无平台依赖）。
8. 不含 P2P：导出明文 JSON 里**不出现** P2P 私钥字段名（与 `crypto::Identity` 的字段集对账）。
9. 文件权限：Unix 下 `0600`；Windows 在同一用户目录下。
10. 判据非空转：把 `secret_key` 换成错误 seed ⇒ 导出时自校验当场红。

## 11. 未决（需要你或安全评审拍板）

1. **是否允许"导出给别人"**：技术上无法阻止（文件可复制）。建议只做警告，不做限制。
2. **是否需要"仅导出、不允许导入"的只读模式**（例如企业发放）：增加复杂度，收益低，建议不做。
3. **口令忘记后的兜底**：建议明确写"无兜底"，不引入恢复码（恢复码等于第二把钥匙，弱化威胁模型）。
4. **是否在导出包里带"设备显示名"**：带（用户能认出这是哪台机器），但它不是秘密。

## 12. 明确不做

- 不导出 P2P 身份密钥、聊天数据库、好友列表、消息内容。
- 不做自动/定时/云备份；不做"导出到剪贴板"。
- 不为了让导入"更方便"而跳过口令（例如操作系统钥匙串自动解锁导出文件）。
- 不把导出当成"账号同步"：没有中心账号，也没有跨设备自动漫游。
