# 通知机器人 v6 代码审计与整改方案

日期：2026-11-17  
范围：`v5.42.0..v6.0.0` 及后续 `4a121ac0` 修复提交；对照部署、接入与重构文档。  
方法：静态源码与提交审阅；未改业务代码，未运行测试、构建、真机或服务端验收。

## 结论

创建机器人、后台轮询、个人会话、群消息、状态控制、免打扰和系统摘要通知的主路径已经存在，但不能判定为可靠闭环。个人消息存在“去重记录已写入、聊天消息没写成”的永久丢失路径；群消息在 ACK 结果未知时可能重复发送；文档承诺的图片未进入聊天；长消息只存 240 字符预览且没有全文入口；群成员面板有 setup 初始化顺序错误。撤销/删除、异步状态呈现也有明显缺口。建议先修复 P1，再统一状态与契约。

产品边界：个人机器人是本机 `bot:<id>` 假身份会话，不是协议好友，也不跨设备同步；群消息由当前网关设备以前缀代发。这与 Frozen Core 不变的设计一致，但“像联系人一样”只覆盖本机入口，产品文案应明确这一点。外部 `gosslan-relay-server` 不在本仓库，本报告不能认证服务端队列、租约、附件、撤销和部署行为。

## 发现

### P1. 个人消息去重与消息落库非原子，重投会吞消息

`src-tauri/src/commands/bots.rs` 的个人 `deliver_event` 先 `append_inbox`，再插入 message、更新 conversation；重复时直接 `Ok(None)`。上层把 `Ok` 当投递成功并 ACK。若 inbox 成功而消息写入失败，重投会命中重复标记并 ACK，聊天消息永久缺失。

**建议：** 将 event_id 去重、消息插入、会话更新置于同一 SQLite 事务；或重复时检查并修复消息行。仅完整落地后 ACK，单独记录 ACK 失败。

**验收：** 注入 inbox 已写、message 写入失败，再投同 event_id，最终恰好一条聊天记录并 ACK；覆盖重启和 ACK 超时。

### P1. 群消息无 event_id 幂等，ACK 不确定时会重复发

同文件群分支直接调用 `send_group_payload`，没有持久化 event_id。取件流程忽略 ACK/NACK HTTP 结果；如果群消息已发出但 ACK 丢失，服务端租约重投会再次产生一条新群消息。

**建议：** 持久化 `(bot_id,event_id)` 投递状态（received/sending/published），提供恢复策略。若现有协议不能保证远端幂等，明确标记“结果未知”及重复风险，不要静默假装 exactly-once。

**验收：** 模拟已发送而 ACK 超时、重启、重复拉取，结果可恢复且重复风险可观测。

### P1. 图片契约没有客户端投递/渲染实现

事件结构有 `images`，但个人消息只写 text `MessageRecord`；群路径也只发送 `entry.text`。接入指南却声明支持图片，形成外部契约与实际结果不一致。

**建议：** 完成附件鉴权下载、大小/类型/hash 校验、持久化、消息关联及个人/群 UI；或暂时拒绝含图片事件并修订接入文档，不能把收到 metadata 当作图片支持。

**验收：** 覆盖个人/群、最大数量和大小、坏 hash、附件缺失、下载失败、重投。

### P1. GroupMemberPanel 立即 watcher 早于 props 初始化

`src/components/GroupMemberPanel.vue` 的 `{ immediate: true }` watcher 在 `const props = defineProps(...)` 前执行并读取 `props.open`。Vue SFC 编译输出仍保持此顺序（本次做了编译产物静态检查，未挂载组件验证）；这会在 setup 期间触发 TDZ `ReferenceError`，可能导致整个群面板打不开。

**建议：** 将 `defineProps` 移到所有读取 props 的 setup 逻辑之前，再注册 watcher。

**验收：** 面板初始 open/closed 两种挂载均无 setup 异常，打开时只加载对应群机器人。

### P1. 长消息只保留 240 字符，全文没有用户可达入口

个人会话将正文截成 240 字符；注释称全文在 inbox/详情，但 v6 界面没有 inbox 读取/详情展示链路。接入方发来的长 Markdown 因而不可读全。

**建议：** 让聊天记录保留全文并设明确安全上限，或增加可发现的全文展开/原文入口；截断必须有恢复路径。

**验收：** 测试边界长度、中文、多字节、Markdown，验证重启后仍能读全；超限有清晰错误。

### P1. Inbox 超过 200 条会裁掉新事件

`load_inbox` 排序为新在前；`append_inbox` 将新事件 push 到末尾后 `truncate(200)`，实际丢掉末尾的新事件，与注释“丢最旧”相反。Inbox 同时承担幂等去重，旧 event_id 被裁掉后还可能再次投递。

**建议：** 明确排序不变量并保留最新 200 条；将去重窗口从可裁剪展示历史中分离，至少覆盖服务器最大重投周期。

**验收：** 连续写入 201 条，保留最新 200 条；重投仍在去重窗口内的旧事件不会重复显示/发送。

### P2. 删除/撤销语义不一致，远端 token 可能仍有效

`bot_delete` 先删除本地记录，再尽力撤销远端；网络错误和 HTTP 非成功状态被忽略，客户端构造失败还会在本地删除后返回错误。删除流程不删个人会话；`bot_set_status(revoked)` 却删除会话。设计文档也混用了“撤销保留历史”和“删除机器人删除会话”。

**建议：** 明确暂停、撤销、删除三种语义。撤销未确认时保存可重试 tombstone 并展示 revoke-pending；统一个人历史保留策略及确认文案。

**验收：** 在线、离线、4xx/5xx、超时、重启后状态真实且可重试，最终收敛；历史行为与文案一致。

### P2. 整条 BotRecord 读改写会并发覆盖字段

`bot_set_dnd`、`bot_set_status` 和轮询完成时读出整条记录，异步操作后再整条保存。并发轮询可能覆盖新 DND/状态，旧快照也可能覆盖失败统计或最近事件时间。

**建议：** 使用字段级原子更新；状态修改带当前状态/版本校验；统计更新只改统计字段，轮询期间再次确认仍为 active。

**验收：** 并发轮询、DND 切换、暂停/撤销时互不回滚，最终值遵守用户最近确认的操作。

### P2. 后台状态不能解释或恢复

轮询后固定写 `pending=0`，即使无事件也更新 `last_event_at`；失败只留计数和通用文本。详情 UI 没显示 pending、lastError、逐事件失败阶段或重试操作。

**建议：** 分开最近成功轮询与最近事件时间；展示队列数、错误阶段/码、下次重试、状态时间线与可执行重试。

**验收：** 网络故障、群失效、落库失败、ACK 失败及恢复后，UI 和持久状态一致，重启后可理解。

### P2. server URL 解析和 scope 输入容错过度

`normalize_bot_server` 用字符串拆分而非标准 URL parser；scope 只识别 `group`，任何未知值都默认个人机器人。

**建议：** 使用 URL parser 校验 scheme/host/port/userinfo/query/fragment 与 localhost 例外；scope 用枚举，未知值拒绝并在创建前提示。

**验收：** 覆盖 IPv4/IPv6 localhost、HTTPS、非法端口、userinfo、query/fragment、非 HTTPS 和未知 scope。

## 可执行整改计划

1. **可靠性修复：** 修复 watcher 顺序；个人落库原子化；群消息引入持久 event_id 状态；修正 Inbox 保留顺序并分离去重记录。
2. **兑现接口契约：** 明确图片支持状态；补齐长文全文入口；统一暂停/撤销/删除与聊天历史语义；严格校验 URL 和 scope。
3. **可运维闭环：** 增加真实 pending/失败原因/重试时间和用户可操作重试；拆分轮询时间与事件时间；改为字段级原子状态更新。
4. **服务端独立审计：** 在 relay server 仓库验证 token scope、速率限制、幂等、附件鉴权/过期、队列上限、租约 ACK、撤销传播和日志脱敏。

## 功能闭环判定

| 能力 | 判断 | 主要缺口 |
|---|---|---|
| 创建个人/群机器人 | 主路径存在 | URL/scope 校验；外部服务契约未验证 |
| 个人消息入会话 | 未闭环 | 落库与去重非原子；长文全文不可达 |
| 群消息投递 | 未闭环 | 重投可重复；图片未投递 |
| Markdown | 部分闭环 | 个人可渲染但被截断；群按纯文本处理 |
| 图片 | 未实现客户端闭环 | 有字段，无下载/关联/渲染 |
| ACK/NACK 恢复 | 未闭环 | 请求错误被忽略，重复路径可丢/重 |
| 暂停/撤销/删除 | 部分闭环 | 远端撤销不可靠、历史语义不一致 |
| 状态可视化 | 不完整 | 无有效 pending、具体错误和逐事件恢复 |
| 跨设备/好友同步 | 按设计不支持 | 本机假身份，需在产品入口明示 |
