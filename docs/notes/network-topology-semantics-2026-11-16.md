# 「我的网络」语义表 · 字段覆盖表 · 不可推断关系清单（2026-11-16）

> 这是[网络拓扑可视化改进方案](network-topology-visualization-plan-2026-11-16.md)**阶段 0 的交付物**，
> 也是阶段 1 视图改造的依据（实现见 `src/utils/topologySemantics.ts` 与
> `src/components/NetworkTopology.vue`）。
>
> **一句话口径**：这张图画的是「**本机正在观察到什么**」，不是全网拓扑。
> 后端没有远端 peer-peer 边 ⇒ 图里**永远只有**「本机 → Peer」的边。

## 0. 产品决策（2026-11-16 已确认）

| 决策点 | 结论 |
|---|---|
| 页面名称 | 「**我的网络**」（原「网络拓扑」—— 那个名字暗示全网图） |
| 视图切分 | **只做「我的邻域」一个视图**（不摆「Mesh 关系」空态入口） |
| 阶段 3（真实全网关系） | **这轮不做** —— 要改网络协议 + 隐私评审 + TTL/上限，是另一个量级的工程 |
| 副标题 | 「从这台设备观察到的网络关系」（把观察主体说清楚） |

## 1. 语义表：每一种线到底表示什么

| 图形 | 语义 | 数据来源（字段） | **禁止**暗示 |
|---|---|---|---|
| 设备节点（圆点） | 一个**稳定设备身份**（`device_id`）；好友/非好友、在线/离线是节点状态 | `peers[].device_id`、`friends[].device_id` | 节点相邻 ≠ 网络相连 |
| 实线边 | 本机**当前选路**：局域网直连 | `Peer.link === "lan"` | 不暗示只有这一条路径 |
| 虚线边（冷灰） | 本机当前选路：路由 IP（对端真实 IP 可达） | `Peer.link === "routed"` | **不是**中继；中间没有转发节点 |
| 点线边（橙） | 本机当前选路：蓝牙直连 | `Peer.link === "bluetooth"` | 不暗示能跨网段 |
| 虚线边（橙） | 本机当前选路：公网中转电路（经中转服务器） | `Peer.link === "relay"` | **中转设备不是节点**，也不等于对端地址 |
| 虚线边（灰） | 本机当前选路：Mesh 多跳（经其他 Gosslan 节点转发） | `get_conv_link` 的 `hop > 0` | **中间节点身份不可见**，只知跳数 |
| 灰色细虚线 | **没有关系证据**（已发现但未建链） | `link` 为空且 `hop = 0` | 不是「离线」、不是「故障」、不是「零跳」 |
| 虚线圆环（本机） | **观察端点**（本机在看你） | `app.device` | **不是**中心枢纽、不是路由中心 |

> **「当前选路」的限定**：前端拿到的是每个 Peer 的**最佳/当前**路径，
> 不是该 Peer 的全部健康路径 ⇒ 图上一条边**不代表只有这一条路**。

## 2. 现有字段覆盖表（今天能给什么 / 不能给什么）

| 想要的语义 | 现在有吗 | 字段 / 缺口 |
|---|---|---|
| 本机到某 Peer 的当前路径类型 | ✅ | `Peer.link`（`lan` / `routed` / `relay` / `bluetooth`） |
| 好友会话的路径与跳数 | ✅ | `get_conv_link` → `{ path, hop }` |
| 到 Peer 的 RTT | ✅ | `Peer.rtt_ms`（可能为 `null`） |
| 首次发现时间 | ✅ | `Peer.first_seen` |
| 设备身份与昵称 | ✅ | `device_id` / `nickname` / `avatar` |
| **任意两个远端 Peer 之间的边** | ❌ | **没有** —— 这是「全网拓扑」无法落地的根本原因 |
| **多跳路径的中间节点身份** | ❌ | 只有 `hop` 数字，没有经过谁 |
| **边的观测时间 / 过期时间** | ❌ | `Peer` 没有 `observed_at` / `expires_at` |
| **一个 Peer 的全部健康路径** | ❌ | 只有当前选路一条 |
| **边的来源（谁观测到的）** | ❌ | 无 `provenance` 概念 |
| **陈旧关系（曾观测到、已过期）** | ❌ | 没有过期判据 ⇒ 本轮只能靠「刷新失败 ⇒ 整页标可能过期」兜底 |

## 3. 「不可推断关系」清单（前端**不许**做的事）

1. **不许画 peer-peer 边** —— 后端没有的事实，画出来就是编的。
2. **不许画中间节点/中转节点** —— 中间是谁不可知；合成的「中枢节点」会被读成真实设备。
3. **不许把「发现到」画成「连上了」** —— `peers` 里有它只说明**观测到**，
   有没有链路要看 `link`。
4. **不许把「当前选路」说成「唯一路径」**。
5. **不许把 `hop > 0` 折成「离线」或「故障」** —— 它是「经别的节点转发」。
6. **不许把「关系未知」折成「没有连接」** —— 未知要有自己的说法。
7. **不许把「多路径」合并成一条**、也不许为「看起来像网状」补三角形或装饰边。
8. **不许按几何相近自动造簇** —— 簇必须基于真实关系或用户标签。
9. **不许把本机画成网络中心/控制点** —— 它是观察端点。

> 这九条在代码里有对应判据（`src/utils/topologySemantics.test.ts` 钉语义，
> `src/utils/designGuards.test.ts` 钉页面形状：合成中枢不许回来、布局必须走邻域、
> 页面名必须说「本机观察」、图与列表必须同源）。

## 4. 本轮做了什么（阶段 1）

| 方案阶段 1 的要求 | 落地 |
|---|---|
| 1. 去掉「合成 Hub 是真实节点」 | ✅ 图里没有合成节点；relay / mesh 的对端就是那个 peer；中转改成**图外的路径摘要卡**（可展开解释「这是路径类型，不是本机控制中心」） |
| 2. 减弱中心辐射的树状观感 | ✅ 本机移到**宽屏左侧 / 窄屏底部锚点**，设备向另一侧展开成扇形（`layoutNeighborhood`） |
| 3. 路径标签准确、区分三类中继 | ✅ LAN / 路由 IP / 蓝牙 / 公网中转 / Mesh N 跳各有标签与线型；relay 与 mesh 在详情里说明「中间节点当前不可见」 |
| 4. 同源列表视图、筛选、刷新状态、最后更新时间 | ✅ 图 / 列表双视图；列表筛选（全部 / 好友 / 离线好友）；顶部显示数据时间，刷新失败时标「数据可能已过期」 |
| 5. 保留稳定坐标、相机归属、懒加载、响应式 | ✅ 坐标由纯函数现算（fx/fy 钉死，无力模拟）；相机一旦被用户接管就不再自动归位；切回「图」时按新尺寸重排一次 |

**阶段 2（非中心布局的稳定化）与阶段 3（真实全网关系）不在本轮范围**：
阶段 2 的「确定性约束布局 + 用户拖拽位置持久化」需要另立方案；
阶段 3 已被产品裁决为**这轮不做**。

## 5. 仍然未验证 / 未覆盖

- **运行时与真机**：本轮只做了源码改造与单测判据，没有跑起应用看真实网络数据
  （无 Peer、离线好友、Mesh 多跳三种真实场景的视觉验收仍 `NOT RUN`）；
- **陈旧关系**（边的 `observed_at` / `expires_at`）后端没有 ⇒ 阶段 3 才有；
- **移动端**：窄屏布局（底部锚点 + 向上扇形）只过了几何判据，没在真机看过。
