> 上游：[设计稿](webhook-notification-bot-design-2026-11-16.md)；
> 服务端契约已固定并交付：[gosslan-relay-server/webhook-api.md](https://github.com/wenzo001/gosslan-relay-server/blob/main/webhook-api.md)
> （`webhook.mjs` + 14 条自测已通过，TCP 盲中继未改动）。
>
> 本文只写**客户端这一侧具体怎么做**：命令、存储、界面、判据、顺序。

## 0. 已经定下来的产品决策（2026-11-16 用户拍板）

| 决策 | 结论 |
|---|---|
| 「链接可以给很多」 | **多个外部发送方共用同一个 bot**（bot 级密钥；不是一 bot 广播多人） |
| 单聊怎么投 | **个人机器人收件箱**（每个机器人一个独立的本机会话；不伪造成 self-DM） |
| 服务端部署 | **独立进程 · 独立端口**（TCP 盲中继进程零改动） |
| 范围 | **端到端最小闭环**：服务端 + 客户端 + 界面 + 文档 + 判据 |

## 1. 客户端要做的事（按落地顺序）

### 1.1 存储（不动 SQLite 表结构）

SQLite schema 属 Frozen Core ⇒ **一律走 `settings` 表**（键值对）：

| 键 | 内容 |
|---|---|
| `bot:<bot_id>` | `{name, server_url, client_token, target, status, created_at, last_event_at, last_error, pending, failed}` |
| `bot_inbox:<bot_id>` | 收件箱消息数组（最近 200 条）：`{event_id, text, source, images[], received_at, state}` |

- `client_token` 是外部凭证 ⇒ **不进日志/诊断/错误响应**；轮换/撤销时一并清掉。
  ⚠️ **命名口径（2026-11-16 实现时改的）**：本地一律叫 `token` 不叫 `secret` ——
  本仓的密钥边界守卫（`check-key-boundary.mjs`）把带 `secret` 的**可序列化**类型判成
  「E2EE 私钥」，而这只是一枚 bearer token（与 relay 的 `token` 同一性质）。
  守卫的口径是「别用密钥命名」⇒ 改名，不加例外。
  **wire 格式不变**：服务端仍然叫 `send_secret` / `client_secret`（见 `webhook-api.md`），
  客户端用 `#[serde(rename = …)]` 映射。
- `event_id` 唯一 ⇒ 收件箱按 `event_id` 幂等（重复投递不重复显示）。
- 收件箱**只在本机**（不跨设备同步、不进好友关系）。

### 1.2 命令（将来新增的机器人命令模块，落在 `src-tauri/src/commands/` 下）

| 命令 | 做什么 | 关键约束 |
|---|---|---|
| `bot_create(name, target, server_url, client_token)` | 向服务端注册 ⇒ 存 bot ⇒ **一次性**回传 `send_token` + endpoint | 凭证只在此处返回一次；服务端返回 4xx 时**不落库** |
| `bot_list()` | 列出机器人（**不含任何密钥**） | 目标失效/服务不可达要带可见状态 |
| `bot_set_status(bot_id, status)` | 暂停 / 恢复 / 撤销 | 撤销**不可逆**（要新建）；同时清掉 client_token |
| `bot_delete(bot_id)` | 撤销并删本地记录 | 提示队列是否清理 |
| `bot_pull_once(bot_id)` | 拉取 → 落本地 → ACK/NACK | **先落库再 ACK**；落库失败 ⇒ NACK 可重试 |
| `bot_inbox(bot_id)` | 取收件箱 | 分页/上限 |
| `bot_set_source_pref` 类 | —— | —— |

- HTTP 客户端走 `reqwest`（已在依赖树里）⇒ **HTTPS 强制**（`http://` 只允许显式开关的本地调试）。
- 拉取 worker：一个后台 tokio 任务，每个启用的 bot 每 `WEBHOOK_PULL_INTERVAL` 拉一次；
  **只在应用运行时**；退出/暂停时停止。
  ✅ 已实现（2026-11-16）：`commands::spawn_bot_poller`（`src-tauri/src/commands/bots.rs`），
  每 **60 秒**一轮、启动后先等 20 秒；只拉 `active` 的机器人；一轮里**逐个**拉
  （一个坏的不卡住整轮）；失败只记一条日志、等下一轮（服务端有租约重投兜底）。
  它登记在 `worker_supervisor::UNSUPERVISED_LOOPS`（**刻意不监督**：死了只影响
  「通知不再自动进来」，用户仍可手动「立即取件」，且没有任何数据会坏）。
  取到后发 `bot-inbox-updated` 事件（载荷 `{bot_id, count}`）⇒ 前端刷新收件箱 + 系统通知。

### 1.3 投递

- **个人收件箱**：写入 `bot_inbox:<bot_id>` ⇒ 界面在「设置 › 通知机器人」里展示
  （机器人名 + 来源标签 + 收到时间 + 图片 + 状态）。
- **群目标**：**走既有群发送链路**（网关设备以自己的身份发群消息）。
  - ⚠️ **wire format 属 Frozen Core** ⇒ 首版**不改线格式**：
    消息正文带来源标记（`【机器人名】` 前缀 + 可选来源标签），界面显示「机器人名 · 由本机代投递」。
  - 「带 `source=webhook_bot` 的结构化元数据 + 能力门控」= 设计稿 Phase 2（要协议评审 + 版本位），
    **不在首版**。
  - 群被删/离群 ⇒ **停止投递并显示失败**，不悄悄改投别的会话。

### 1.4 界面（复用现成组件，不另造控件）

- **设置 › 通知机器人**（新分组）：
  - 列表：名称 / 投递位置 / 状态 / 待投递与失败数 / 最近收到时间 / 服务连接状态；
  - 创建：名称 → 目标（本机收件箱 | 选一个群）→ 服务地址与客户端令牌 → 创建 →
    **一次性展示 endpoint + send_token + 可复制的 curl 示例** → 自测按钮；
  - 每个机器人：暂停 / 恢复 / 轮换密钥 / 撤销；
  - 收件箱：机器人消息列表（图片可预览）。
- 文案：zh-cn 与 en-us **同步**；外部来源名与正文一律当**不可信文本**（转义 + 限长）。
- 系统通知只给「有新机器人消息」的摘要，**不放正文与图片**。

### 1.5 判据（这一轮的验收）

| 判据 | 形式 |
|---|---|
| 凭据不进日志/诊断/列表响应 | Rust 单测 + 源码形状判据 |
| 重复 `event_id` 不重复显示 | Rust 单测（收件箱幂等） |
| **先落库再 ACK** | 源码形状判据（ACK 调用必须在落库之后） |
| 撤销后密钥全失效 | Rust 单测（清 secret + 服务端 401） |
| 界面密钥**只显示一次** | 前端判据（不在列表里回显 secret） |
| 图/列表口径一致 | 前端判据 |
| HTTP 强制 HTTPS | Rust 单测（`http://` 被拒，除非显式本地开关） |

## 2. 明确不做（这一轮）

- 结构化 `webhook_bot` 元数据 + 能力门控（Phase 2，需协议评审）；
- 逐成员回执（Phase 2）；
- 多目标广播（用户已选「多发送方共用一个 bot」）；
- 端到端加密的附件信封（Phase 3）；
- 服务端的队列监控面板 / 租户隔离（Phase 3）。

## 3. 风险与兜底

| 风险 | 兜底 |
|---|---|
| 服务端不可达 | 机器人状态显示「服务不可达」；外部提交由服务端排队，网关恢复后补取 |
| 网关离线 | 事件留在服务端队列；恢复后取件（租约到期重投） |
| ACK 丢失 | 事件重投；客户端按 `event_id` 幂等，不重复显示 |
| 队列满 | 服务端返回 503（**不假 202**）；界面显示失败数与原因 |
| 密钥泄漏 | 立即撤销（服务端 401）+ 重新生成 |
| 群目标失效 | 停止投递 + 显示失败 + 用户重新选择（**不自动改投**） |
