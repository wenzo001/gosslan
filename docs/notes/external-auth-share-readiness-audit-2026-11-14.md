## 1. 结论

当前项目已经具备**桌面端 RP 设备绑定/登录协议的客户端实现雏形**：Gosslan 可读取 RP 事务、展示原生确认页、以 RP 专属 Ed25519 密钥签署短时断言，并在设置中查看和撤销本地绑定。桌面外链窗口也已隔离第三方网页权限。

但它还不是可直接交给任意外部应用生产接入的完整快捷登录产品：项目没有中心账号或用户资料服务，移动端系统级 App Link/Universal Link 未配置；撤销目前只在本地生效；首绑失败可能留下本地已激活、RP 未登记的状态；真实打包唤起、RP 端生产实现和端到端验收未证实。

**外部页面分享到 Gosslan 聊天的闭环尚未实现。** 现有分享主要是本地共享目录/文件传输；没有通用网页分享请求、系统分享目标、`/share` 深链入口、会话选择和显式发送面板。现有设计草案已描述这些目标，但设计稿不等于运行功能。

因此，当前可进入**受控桌面联调/封闭试点准备**，不能宣称“外部应用可直接生产接入”，也不能宣称“任意外链都能一键分享到聊天”。

## 2. 能力盘点

| 能力 | 当前判断 | 证据与边界 |
|---|---|---|
| RP 发起设备绑定/快捷认证 | 部分已实现 | `device_auth` 命令、RP metadata/request 校验、RP 专属密钥、JWS 签名、用户确认和绑定列表均已存在。它证明某个 Gosslan 安装持有 RP 密钥，不证明自然人身份。 |
| 用户信息同步 | 未实现为中心化身份能力 | 只有协议 allowlist 中的 `device_subject`、`device_public_key`、可选 `nickname`。没有全局 Gosslan 账号、邮箱/头像资料服务或用户指纹服务。昵称是用户可改的设备资料。 |
| 桌面深链唤起 | 代码路径存在，系统验收未完成 | 桌面配置注册 `gosslan` scheme，解析器接受授权链接；但真实安装包中的系统协议注册/点击唤起仍需逐平台验收。HTTPS 授权链接语法不等于 iOS Universal Links 或 Android App Links 已配置。 |
| Android/iOS 自动唤起 | 未就绪 | Android manifest 目前只有 launcher 入口，没有对应 VIEW/App Links intent filter；未见 iOS Associated Domains 配置。当前不能承诺移动端网页点击后自动回到 App。 |
| 外链内置窗口隔离 | 已有安全边界 | `link` 窗口加载 HTTP(S)，不在默认 capability 窗口集合内，导航只允许 HTTP(S)。源码未发现向远端页面注入通用 JS/Tauri bridge。 |
| 外链网页直接调用 Gosslan | 未实现 | 由于隔离设计，网页不能调用 Gosslan IPC，也没有受限的认证/分享桥接 API。这是安全边界，不应通过开放通用 `invoke` 绕过。 |
| 网页链接分享到聊天 | 未实现 | 无通用 share request API、分享深链、操作系统分享目标、聊天会话选择/草稿/发送确认界面。普通复制粘贴不构成一键分享闭环。 |
| 外部分享目标（微信/QQ/飞书等） | 未实现 | 当前无这些平台的官方 SDK 接入，也没有原生系统分享目标验收。设计上应由系统分享面板提供实际可用目标；不可用时提供复制链接/回到 Gosslan 的明确退路。 |
| 外部接入文档 | 仅有设计草案 | `external-app-device-auth-design-2026-11-13.md` 描述了协议和分享目标，但 RP mock 是本地内存型契约演示，不是生产后端、SDK 或已验证 starter。 |

## 3. 主要实现与设计风险

### P1：绑定状态与 RP 事务可能分叉

首绑路径在 RP 回调确认前写入本地 active binding。如果 RP 决策请求失败，用户本机可能显示已授权，但 RP 尚未登记该公钥。应将绑定建模为 `pending_registration → active`，只有 RP 成功确认后才激活；失败、超时和重试必须具备幂等键与可见状态。对已存在绑定的重新认证也要明确它是否更新 `last_used`、是否消费一次性事务。

拒绝操作会先清理本地 pending，再尽力通知 RP。若网络失败，RP 页面可能一直等待到事务超时。界面应区分“本机已拒绝”和“RP 已收到拒绝”，并提供事务状态/重试或明确过期时间。

### P1：撤销语义是单边的

设置页撤销只把 Gosslan 本地绑定标为 revoked；RP 账户侧公钥不会自动撤销。外部接入契约必须写明两边分别撤销，并提供 RP 账户安全页查看/撤销设备的要求。若产品希望一键双向撤销，需要定义 RP 撤销 API、失败重试和最终一致性状态。

### P1：移动端交接能力缺失

解析器能识别授权链接，不代表系统能把链接路由到应用。Android App Links 要有 manifest intent filter、域名 assetlinks 关联和安装验证；iOS Universal Links 要有 Associated Domains 与站点关联文件。当前应把移动端入口列为未完成的产品/发布能力，不能只凭解析函数宣布支持。

### P1：密钥保护与账号安全边界需定案

RP 专属私钥当前保存在本地 SQLite。仓库既有设备身份决策允许本地数据库存储密钥，但本协议面向外部登录，应单独做威胁模型和平台保护决策：是否沿用数据库加权限保护、是否使用平台 Keychain/Keystore、备份/迁移会怎样影响绑定，以及用户清除数据后如何恢复。不能将现状描述成硬件指纹或硬件保护密钥。

### P2：请求 TTL、取消和可恢复状态需要统一

客户端要求请求尚未过期，但服务端必须负责短 TTL、一次性消费、重放防护、挑战绑定与登录浏览器会话绑定。客户端网络超时、用户关闭确认页、重复唤起、同一事务并发处理、App 重启后的过期清理都应有明确可见状态和终态。待确认队列的容量限制应在满载时反馈“暂不能处理”，而不是让用户误以为链接无效。

### P2：分享与认证不可混成网页桥

分享是“用户选择内容和接收会话后发送”；认证是“用户批准一次 RP 挑战并签署”。不能由网页直接请求私钥、构造任意消息或静默发消息。未来若增加网页到原生能力的入口，只暴露窄操作（例如创建待审分享请求），并绑定来源、一次性 nonce、过期、用户手势和原生确认；不提供任意 Tauri command bridge。

## 4. 产品目标一致性

现有产品的主身份是本地安装级设备身份和 P2P 好友关系，不是中心化用户账号。把当前功能称为“绑定 Gosslan 用户、同步全局资料、提供不可变用户指纹”会与实现事实及现有产品边界冲突，也会暗示项目并不存在的身份保证。

一致的产品描述应是：**外部 RP 可把某个 Gosslan 安装登记为可撤销的设备凭证；每次登录/绑定由用户在 Gosslan 原生界面确认；RP 自己负责账号、会话、资料和撤销。** 若未来要做全局 Gosslan 账号与用户资料同步，应作为独立产品决策，另行设计账号服务、恢复流程、隐私与运营责任。

分享产品目标也应保持分层：任何 HTTP(S) 网页都可通过系统分享能力或复制链接进入 Gosslan 的统一分享流程；用户先选会话、查看内容，再明确发送。只有完成各平台官方集成和审核后，才显示品牌专属快捷目标。分享动作不附带登录 assertion、Cookie、网页 DOM 或设备私钥。

## 5. 推荐最佳实践与落地计划

### 阶段 A：收敛协议与事务状态

1. 确认产品术语为“设备绑定/设备快捷认证”，不使用“用户指纹”“永久身份”等表述。
2. 定义状态机：`created → awaiting_device → approved/denied/expired/cancelled`；绑定另有 `pending_registration/active/revoked/registration_failed`。
3. 规定 RP session/CSRF 绑定、挑战一次性消费、idempotency key、最大 TTL、拒绝可观察状态与撤销双边语义。
4. 决定 SQLite 密钥保护、平台密钥库是否需要、备份/迁移/清除数据行为。

### 阶段 B：完成桌面集成试点

1. 以现有 RP mock 做协议联调，再由一个真实 RP 后端实现事务存储、登录会话绑定、公钥登记、状态查询和 RP 侧撤销。
2. 验收已安装/未安装、重复链接、过期、拒绝、网络断开、RP 回调失败、App 重启、撤销、密钥丢失等路径。
3. 在签名桌面安装包验证协议注册和浏览器跳转；覆盖 macOS、Windows 的安装、升级和卸载行为。
4. 只有回调成功、绑定状态一致、重复事务不重复授权且错误可见后，才考虑桌面封闭试点。

### 阶段 C：建立移动端链接交接

1. Android：声明 HTTPS App Links、验证域名关联文件、验证签名包和系统选择器行为。
2. iOS：建立 Associated Domains、站点关联文件和已安装/未安装回退路径；同时确认 Tauri iOS 工程实际生成与签名配置。
3. 两平台都验证冷启动、前台唤起、应用未安装、链接无效、重复点击和返回原页面。

### 阶段 D：落地网页分享闭环

1. 为分享定义独立短时 `share_request`，服务端只返回标题、HTTP(S) URL、用户编辑文本和过期信息；禁止返回认证 token 或任意账号资料。
2. 建立统一分享面板：内容预览/编辑、最近会话、联系人/群搜索、接收对象确认、发送按钮、取消返回。
3. 分享发送只在用户点击“发送到〈会话〉”后调用现有消息发送入口；失败时保留草稿并允许重试，不把取消显示成发送成功。
4. 普通网页走系统分享目标或复制链接；RP 集成页使用一次性 share request。认证确认页面不显示分享入口。
5. 首期不自动抓取网页预览，降低 SSRF、跟踪请求及远端内容风险；后续若增加预览，由独立安全代理实现并允许关闭。

### 阶段 E：外部接入文档与开放门槛

正式对外开放前，需交付版本化 RP 接入文档、服务端参考实现、字段/错误码表、密钥轮换/撤销说明、桌面与移动端关联配置、沙盒测试环境、生产验收清单和兼容策略。当前 `device-auth-rp-mock.mjs` 只能作为协议示例，必须明确其内存存储、自签证书和无真实账号会话限制。

## 6. 发布准入判据

只有以下事项都有可复现证据，才可将“外部直接接入”标为可用：

- RP 事务从创建、原生确认到 RP 会话完成全链路成功；批准、拒绝、过期、重复和网络失败均有确定结局。
- 本地与 RP 的绑定/撤销状态无歧义，失败可重试或明确恢复方式。
- 签名断言仅含协议约定字段，不泄露全局设备 ID、P2P 私钥、Cookie 或长期 token。
- 桌面签名安装包真实唤起通过；Android/iOS App Links/Universal Links 分平台通过。
- 外链窗口不能调用任意本机命令；所有远端回调严格限制 HTTPS 同源与重定向。
- 分享流程经用户选择接收人并显式发送；取消不会发消息，失败保留可恢复草稿。
- 外部 RP 文档、示例、错误码和生产注意事项与实际客户端版本一致。

## 7. 本轮未验证项

- 未运行测试或 RP mock；未构建/安装签名发行包。
- 未验证 macOS/Windows 系统协议注册，也未在 Android/iOS 真机验证 App Links。
- 未验证 RP 真实服务端对事务、账号会话、撤销、重放和并发请求的实现。
- 未验证系统分享面板能否在各桌面/移动系统向 Gosslan 返回内容。
